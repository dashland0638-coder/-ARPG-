## 1. 二つのカテゴリー

マップを作る前に、**そのマップの主目的がどちらか**を一つ決めて書く（§6 の宣言）。

| | A. 閉じたマップ（ストーリー体験型） | B. フィールドマップ（移動・探索体験型） |
| --- | --- | --- |
| 問い | 「この場所で何が起きたのか」 | 「この先に何があるのか」 |
| 主目的 | 事件・人物・怪異・謎・歴史を体験させる | 移動そのものに意味を持たせ、道中の発見と遭遇を楽しませる |
| 構造 | 導入・展開・クライマックス・結末。進行をある程度制御する | 広い地形・複数の経路・寄り道の余白。目的地は見えている |
| 主な中身 | 固有 NPC・イベント・会話・謎解き・ボス・鍵と仕掛け | ランドマーク・遠景・リスキーモブ・強敵・依頼・採集・発見 |
| 演出の密度 | 高い（場所ごとの独自体験） | 低め（間がある。景色と移動の時間を味わわせる） |
| 第一章の例 | 森の洋館・宵待ちの村・幽霊船・時計塔 | 道（新）（導入として、少しだけ） |
| 旧来の例 | 地下水路・古代神殿 | ― |

## 2. A. 閉じたマップの設計原則

1. 明確な導入・展開・クライマックス・結末を持つ
2. マップの構造と物語を結びつける（部屋の並び・鍵・一方通行・帰れない場所が、物語の意味を持つ）
3. 固有の NPC・イベント・会話・謎解き・ボスを置く
4. 進行をある程度制御し、演出の密度を上げる（見せてから話す、DUNGEON_RENDERING §3）
5. 一本道・分岐・鍵・仕掛けは、物語に合わせて選ぶ（分岐のための分岐を作らない）
6. その場所だけの体験を優先する（幽霊船の「帰れない」、時計塔の「縦に登る」、村の「暮れていく」）

しないこと:
- ランダム探索・大量のサブミッション・討伐数の依頼を詰め込まない
- 物語と関係のない寄り道で、演出の流れを切らない

## 3. B. フィールドマップの設計原則

1. 広い地形と複数の経路を用意する
2. 遠景・地形・ランドマークで探索の意欲を引き出す（目的地や次のランドマークが遠くに見える）
3. 移動中に、リスキーモブや強敵と出会う機会を作る
4. 依頼・討伐・探索・採集・発見などのサブミッションを置く
5. 一本道に限らず、寄り道できる余白を作る
6. 移動の時間と、出会う物に意味を持たせる（時間帯・天候・地域の事情）
7. 目的地までの道中そのものを、ゲームの体験にする

**広いだけのマップにしない。** 次の三つの「理由」を、必ずマップの中に置く:

| 理由 | 例 |
| --- | --- |
| 移動する理由 | 目的地が見えている。次のランドマーク・野営地が見えている |
| 寄り道する理由 | 隠し道の先の宝箱・眺めの良い場所・依頼の対象・珍しい採集物 |
| 危険を冒す理由 | リスキーモブの先にある近道・報酬・発見 |

### 3-1. リスキーモブ
- 既存の強さの枠組み（強モブ・強敵、`docs/PROGRESSION.md`・`src/core/enemy-tier.js`）の上に作る。新しい区分を別に作らない
- 通常の敵より**明らかに危険**にする（見た目・大きさ・歩き方・音で、近づく前に分かる）
- 「見つける → 避ける／挑む」の判断が生まれる配置にする（避けられる道を残す。挑んだ時の見返りを用意する）
- 不意打ちで倒されるだけの置き方をしない（予兆を必ず出す。COMBAT.md の予兆の作法）
- 強さは、その時の戦闘の人数で決める（第一章は主人公＋支援の 2 人、DEC-025 E-2。第二章以降の人数はその章の仕様に従う）

### 3-2. 依頼（サブミッション）
- 討伐数を稼ぐだけの依頼にしない
- フィールドの地形・生態・地域の事情と結びつける（例: 谷の水位・原野の獣の通り道・山道の遺構）
- 依頼の対象は、マップの上で「そこにある理由」が見える所に置く

### 3-3. しないこと
- フィールドを物語のイベントだけで埋め尽くさない（会話の帯で移動が止まり続ける作りにしない）
- 目的地の見えない迷路にしない
- 寄り道の先を空にしない（寄り道させるなら、何かを置く）

## 4. 両方を組み合わせる時の判断

組み合わせは認める。ただし**主目的を一つに決めて、もう一方は従にする**。

| 判断 | 基準 |
| --- | --- |
| フィールドに物語のイベントを置く | 置き場所は野営地・ランドマーク・エリアの境など「立ち止まる理由のある所」。**止める帯**（操作が止まる一幕）は、エリアに 1〜2 か所まで。**止めない帯**（歩きながらの掛け合い・一行の発見の一言）は数えない。第一章の道（新）の今の帯は直さない（DEC-028 J-3）。新しいフィールドから守る |
| 閉じたマップに寄り道を置く | 物語の情報（古い記録・痕跡）を持つ寄り道だけ。報酬だけの寄り道は置かない |
| フィールドの中に閉じた区画を作る | 遺構・洞窟など、入口で空気が変わる場所として作る（その区画の中は閉じたマップの原則で作る） |
| 迷ったら | 「この場所でプレイヤーに残したい一つの記憶」は何かを書き、それが物語ならA、移動と発見ならB |

## 5. 第一章と第二章以降の役割

| | 第一章 | 第二章以降 |
| --- | --- | --- |
| 閉じたマップ | 主役（洋館・村・幽霊船・時計塔） | 引き続き、物語の中心 |
| フィールドマップ | 「道（新）」で**少しだけ**体験させる導入 | 本格化する |
| フィールドの要素 | 開けた景観・遠くの目的地・地形で変わる景色・道中の会話・野営地（休む・支援を選ぶ）・時間の移り変わり・一度きりの強敵 | 多様なリスキーモブ・地域ごとの依頼・固有のサブミッション・複数経路の探索・危険地帯・固有の報酬と発見・地域ごとの生態と環境の変化 |
| 目標 | 「こういう広い世界を冒険できるのか」という期待を残す | その期待に応える |

第一章にフィールドの要素を詰め込みすぎない（GAME_DESIGN「過剰な育成システムを Chapter 1 に持ち込まない」と同じ考え）。

## 6. マップを作る時の宣言（設計書の冒頭に書く）

```
- カテゴリー: A（閉じたマップ）/ B（フィールドマップ）
- 残したい一つの記憶:
- 導入 / 展開 / クライマックス / 結末（A）または 移動する理由 / 寄り道する理由 / 危険を冒す理由（B）:
- 従の要素（もう一方のカテゴリーから借りるもの）と、その上限:
- 描画の単位（今いる区画 / 今いるエリアと隣）: DUNGEON_RENDERING.md に従う
```

## 7. 技術的な共通方針（今ある作法）
- **閉じたマップ**: 今いる部屋・区画を描き、外側は黒（DUNGEON_RENDERING §1・§2）
- **フィールドマップ**: 今いるエリアと隣のエリアだけを描く（道（新）の `road2VisibleAreaIds`）。遠景は軽い板と霧で見せる。同じ形は InstancedMesh にまとめる（ROAD-VISUAL-002 / DEC-025 E-6）
- **時間帯**: 物語の進行で動かし、実時間の時計は使わない。引き返しても巻き戻らない。光の色は数秒かけて補間する（宵待ちの村 DEC-006 EX-2、`src/core/dusk-light.js`。道（新）は ROAD-VISUAL-004）
- **保存**: ダンジョンの中の位置は保存しない（PROGRESSION）。フィールドは到達したエリアの番号など、最小の項目だけ（DEC-025 E-3）。時間帯などは進行から導き、保存しない
