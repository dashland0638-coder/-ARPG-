## 0. 結果の書き方

各項目に次の4つのどれかを付ける。

| 記号 | 意味 |
| --- | --- |
| **P** = PASS | 書いてあるとおりに動いた |
| **F** = FAIL | 書いてあるとおりに動かない。§9 の重さ（Critical / Major / Minor）も書き、下の「FAIL のときに書くこと」を残す |
| **O** = OBSERVATION | 動くが、見た目・テンポ・分かりやすさは直した方がよい（例: 遠い、長い、見えにくい） |
| **N** = NOT TESTED | 見られなかった（途中で倒れて別の道を通った、など） |

迷ったら **O** にしてメモを書く。FAIL か OBSERVATION かは Agent が後で整理する。

### ID の横の印（自動テストとの関係）

| 印 | 意味 |
| --- | --- |
| 🤖 | E2E（ブラウザの自動テスト）で、画面上の動き・表示を確認している。ただしセーブを差し込んで区間ごとに見ているだけで、**実機・通しでは未確認** |
| 🧪 | unit テストで、台詞・配置・条件のデータだけを確認している。**画面に出るか・見え方は未確認** |
| 👁 | 自動テストが無い、または見え方・間・手触りなど **実機でしか判定できない** |

🤖 / 🧪 は **項目の一部だけ** を見ていることがある（例: 台詞は見ているが、間や見え方は見ていない）。

**🤖 / 🧪 も、実機で見るまでは P にしない。** 印は「どこが壊れていそうか」の目安で、自動テストの合格は実機での確認ではない。洋館の 👁 のうち B-05〜B-09・B-12〜B-13・B-19〜B-21 は、テストが未 merge の PR（#39〜#43）にある。

### FAIL のときに書くこと

1. ID と重さ（Critical / Major / Minor）
2. 場所（ステージ・部屋・ミニマップの地名）
3. 直前にした操作（例: 扉を抜けた直後に回避）
4. 期待していたこと（表の「期待結果」）と、実際に起きたこと（出た文言はそのまま書き写す）
5. もう一度やって同じことが起きたか（起きた / 起きない / 試していない）
6. スクリーンショットか画面収録（iPhone の画面収録が楽）。固まったときは何秒待ったか
7. その後どうしたか（続けられた / 酒場からやり直した / アプリを開き直した）

## 9. 重さの定義（FAIL に付ける）

| 重さ | 例 |
| --- | --- |
| **Critical** | 進行不能（詰み）、セーブ破損、Chapter 1 を終えられない、クラッシュ・真っ白 |
| **Major** | 主要キャラクターが加入しない、主要な演出（交代・分離・再会・跳躍・島・正式加入・最後の会話）が欠ける、禁止要素が出る、明らかに誤った挙動で戦闘・進行が成立しない |
| **Minor** | 見た目・テンポ・文言・位置の小さなずれ（進行と体験の骨格は成立している） |

見た目・テンポの問題（「遠い」「長い」「見えにくい」）は、原則 **OBSERVATION**。Agent は勝手に大きく直さず、Observation / Human Escalation として扱う。

## 10. Content Ready 判定

**CONTENT READY = YES** は、次の **全て** を満たす場合だけ。

1. Main route（A-01〜A-19）を実機で最後まで完走した
2. 重大な進行不能が無い（Critical FAIL が 0）
3. Chapter 1 の主要演出が成立している（交代・分離と再会・崩壊と跳躍・島・正式加入・最後の会話）
4. キャラクター加入が成立している（鍛冶士・魔法使い・弓師・盗賊・影の旅人）
5. 時計塔 → 島 → 道 の接続が成立している（D-13〜D-19、E-01〜E-04）
6. 最終戦闘 → 丘 → 酒場 → Ending が成立している（E-15〜E-22）
7. Chapter 1 の禁止要素が出ない（C-14〜C-17、D-20、G-05）
8. Critical / Major の FAIL が 0

Minor の FAIL と OBSERVATION（見た目・テンポ）が残っていても、それだけでは NO にしない。

**NOT READY** は、次の **いずれか** がある場合。

- 進行不能 / セーブ破損 / Chapter 1 を終えられない
- 主要キャラクターが加入できない
- 主要シナリオ演出が欠けている
- Chapter 1 の禁止要素が出る
- Critical / Major の gameplay bug

## 12. 既知のことと、混ぜないもの

- **自動テストで見ている範囲**: 区間ごとの unit / 状態注入 E2E（`.ai/reports/CQ-01-analysis.md` §4）。島の遠景・跳躍の間・手触りは自動テストでは判定できないので、この通しで見る。
- **既知の不安定なテスト**（この判定に混ぜない）:
  - TF-02: `mansion-enemies` の猟犬の予兆。未調査
  - TF-03: `combat-events-layout` :263 / :296 のタッチの重なり。**CI の失敗時に原因の手がかりを記録する仕組みを merge 済み（#65）。根本原因は未確定**（実際のタッチ UI の不具合かどうかも未確定）。実機でインタラクト（話しかける・調べる）のボタンが左の仮想スティックに重なって見えたら、OBSERVATION として場所とスクリーンショットを残す
  - TF-04: `chapter1-tower-to-road` の長い方が、長い一括実行の後半で時間切れになることがある（低 fps のため。ゲームの不具合ではない）
- **数値**: 見た目・テンポ・強さで気になった点は OBSERVATION に書く。数値を変える場合は Agent が HE-3（現在値・実測値・問題・推奨値・理由・影響）で Human に確認してから。
