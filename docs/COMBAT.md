# Combat

戦闘システムの正式仕様。職業ごとの性格づけは [CHARACTERS.md](./CHARACTERS.md)、
設計思想の背景は [GAME_DESIGN.md](./GAME_DESIGN.md) を参照。

詳細な実装経緯・数値の根拠はルートの `COMBAT_DESIGN.md` / `ARPG_INTEGRATION.md` にある。

## Normal Attack

**確定**

- 通常攻撃は短い間隔で連続して使用できる
- 長押しによって自動的にコンボが継続する（オートコンボ）

**実装事実**（`src/legacy/parts/13-update-loop.js`、STEP 3-A.2）

- タップでも長押しでも通常攻撃。押している間は `state.attackCD` が明けるたびに
  `tryAttack()` を1回呼ぶだけで、専用タイマーも攻撃速度補正も持たない
- 押した瞬間に1発目が出る
- 接地中のみ繰り返す。空中（切り上げ／落下攻撃）は「1入力につき1アクション」
- コンボ段数は職業ごとに異なる（大剣3段 / 双剣4段 / 杖2段 / 弓4段。alt武器は一律2段）

## Charge Attack

**確定** — 独立したチャージ攻撃システムは廃止する。
チャージ的なモーションが必要な場合は、武器スキルなどへ再利用する。

**実装事実** — 攻撃ボタンの tap/hold 判定（`ATTACK_TAP_THRESHOLD` / `state.charging` /
`chargeT` / `chargeCD` / スタミナの継続消費）は削除済み。
溜め技だった variant `dash` は威力・移動・VFX・モーションを変えずに
スキルボタン側の選択肢（`state.skillChoice`）へ移してある。

なお **スキルボタン側の溜め**（`state.skillCharging`、魔法使いの照準系など）は
この廃止の対象外で、従来どおり残っている。

## Step

**確定**

- 通常ステップを基本移動・回避として使用する
- 職業ごとにステップの性質を差別化する

**実装事実**

- 回避中は無敵時間があり、その最中に被弾を検出すると反撃ダメージ +50% の窓が開く
  （ジャストドッジ）
- 回避直後には回避攻撃の受付窓（`dodgeAttackWindowT`）があり、
  回避攻撃はダメージ ×1.5・体幹 ×2.5
- 差別化は現状 **モーションのみ**（`DODGE_MOTION`）。
  無敵窓など時間に関わる値は4職共通
  - 剣士: 大きく丸まる正統派ロール
  - 盗賊: 低く速いタンブル
  - 魔法使い: ロールではなく短い明滅
  - 弓師: 横っ跳び
- 鷹の目のみ、回避直後に限り狙い筋補正の角度が広がる（約155度 / 1.1秒）

**未確定** — 職業ごとに無敵時間・距離・硬直まで差別化するかどうか。

## Skill

**確定**

- プレイヤーはボスから取得したスキルを装備する
- 基本的に2つのスキルを装備する（`CHAPTER1_SKILL_SLOTS = 2`。Chapter 2 でも上限は変わらない）

**スキルカテゴリ（設計確定案）**

- projectile
- counter
- summon / trap
- recovery / self buff

最終的なスキル一覧は **未確定**。

**実装事実**

- Chapter 1 の主人公は Skill 1 だけを持って酒場を出る
- ダンジョン中盤、同行者の行動を見て主人公自身が Skill 2 を **閃く**
  （教わるのではない）。閃いた時点で自動装備され、プレイヤーの操作は要らない
- 現行の Skill 2 の実体は職業固定（`SKILL2_BY_CLASS`）

| 職業 | Skill 2 | 効果 |
| --- | --- | --- |
| 剣士 | 地裂斬 | 地を裂きながら前方遠くまで斬撃を飛ばす |
| 盗賊 | 三連投げナイフ | 短剣を3連続で投げつける |
| 魔法使い | 護りの魔球 | 両脇に追尾する魔球。接近で自爆特攻し、被弾時は身代わりになる |
| 弓師 | 爆弾投げ | 目の前に広範囲の爆弾を投げ込む |

- 必殺技（ult）はスキルとは別枠。上位職には専用必殺技がある（`JOB_ULT_BY_JOB`）

### Loadout Change Rule

**確定**（`core/chapter1-skills.js` の `loadoutChangeState()` が判定）

```
探索中                         → 変更可能
敵認識・戦闘体勢               → 変更不可
戦闘終了（体勢が切れる）        → 再び変更可能
イベント・ボス演出中           → 変更不可
```

「戦闘体勢」の判定に新しいフラグは作らない。既存の `state.combatStanceT`
（`core/combat-stance.js`）をそのまま使う。
購入・ランク上げは「組み替え」ではないので制限を受けない。

## Stagger（体幹）

**確定**（`COMBAT_DESIGN.md` §8-3 の「正式仕様（現行）」を採録）

| 項目 | 値 / 挙動 |
| --- | --- |
| 体幹最大値（通常敵） | 55（強敵130・ガード持ちは ×1.3） |
| 体幹最大値（ボス） | 180〜320 に clamp（HPインフレと切り離す） |
| 1撃の基本値 | `BASE_STAGGER_GAIN = 10` ×（技倍率 × クラス倍率 × 能力倍率 × パニッシュ倍率） |
| 70%到達 | 大怯み（`hurtT` を0.5秒へ延長＋トースト） |
| 100%到達 | ダウン（AI停止 2.2〜3.0秒） |
| 自然回復 | 通常敵 16/秒、ボス 12/秒 |
| 回復開始遅延 | 体幹が増えてから1.5秒は減衰しない。増えるたびにリセット |
| ダウン復帰後 | `posture = 0` / 1.5秒は再び溜まらない（再ダウン防止） |

設計意図は「殴っても崩せる／読めばもっと速く崩せる」。
連打だけが最適解にならないよう、手を止めれば1.5秒後に従来速度で戻る。

**実装事実** — パニッシュ窓（振りかぶり ×1.6 / 振り抜き ×1.3）、
回避攻撃 ×2.5、落下攻撃 ×3.0、Perfect Brace ×2.2、Enemy Step +55。
強モブには Super Armor / Guardian（正面からの判定を大きく減衰）があり、
「通常敵は殴れば攻撃を潰せる／強モブは潰せない」という段差を作っている
（`core/enemy-tier.js`）。体幹を割り切ると Break → EXECUTE →
Execution（処刑）へ繋がる（`core/execution.js`）。

## Air Action

**確定** — 空中でのスキル発動は禁止（`blockedInAir('SKILL')`）。
空中で可能なのは切り上げ・落下攻撃など、接地攻撃とは別系統の限定的な行動のみ。

## Hit Feedback

**確定** — 通常攻撃では次を重視する。

- hit-stop
- 小さな Hit VFX
- 攻撃の手応え

**実装事実** — hit-stop は設定項目（`hitStopIdx` / `state.hitStopScale`）として
プレイヤーが強度を変更でき、設定はセーブされる。
攻撃SE・見た目の振り抜き・当たり判定は `core/swing-timing.js` の
`JOB_SWING_IMPACT_FRAC`（impactFrac）を共通参照し、必ず同じ瞬間に揃う。

## Enemy Behavior

**確定**

- 敵・ボスは瞬時に180度向き直らない（回転速度を持つ。`core/enemy-facing.js`）
- 攻撃後には「身体の流れ」があり、そこがプレイヤーの有利な時間になる
- 敵の情報は距離・遮蔽で制限される（visible / sensed / hidden の3段階。
  `core/enemy-visibility.js`）

## Mage

**確定（重要な固定仕様）**

- 魔法に **属性システムを導入しない**。属性相性で殴り合う設計にしない
- 魔法使いは次の要素で戦う
  - 距離
  - 誘導
  - デコイ
  - ステップ
  - 魔法弾
  - 位置取り

戦術の骨格:

```
距離管理 → 敵の誘導 → デコイ → 魔法攻撃
```

**実装事実** — 属性・属性相性のシステムはコード中に存在しない（仕様と整合）。
魔法使いは `range:'ranged'`、通常攻撃は魔法弾、必殺技「メテオフォール」は
照準式（押している間に爆発半径とダメージが伸び、MPを消費し続ける）。

### Mage Skill 1（ステップ＋幻影デコイ）

**設計確定案 — 正式決定ではない**

- ステップで移動すると同時に幻影デコイを残す
- 敵をデコイへ誘導する
- その後、距離を取って魔法弾などで攻撃する
- 通常ステップとの使い分けを重視する

**判断の根拠**: 既存ドキュメント（`COMBAT_DESIGN.md` / `ARPG_INTEGRATION.md` /
`MANSION_SCENARIO.md`）にこの案の記述は無く、実装にも「デコイ」「幻影」に
相当するコードは存在しない。現行の魔法使いの Skill 2 は「護りの魔球」で、
デコイではない。したがって本ドキュメントでは **設計確定案** として記録し、
正式決定として実装を縛らない。正式決定する場合は `.ai/decisions/` に
Decision を残したうえで、本節のマーカーを **確定** へ更新すること。
