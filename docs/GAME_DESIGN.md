# Game Design

ゲーム全体の基本方針。個別仕様は [CHARACTERS.md](./CHARACTERS.md) /
[COMBAT.md](./COMBAT.md) / [PROGRESSION.md](./PROGRESSION.md) /
[SCENARIOS.md](./SCENARIOS.md) を参照。

## Genre

**確定** — 見下ろし型（トップダウン）3D ARPG。Web（Vite + Three.js）で動作する。

## Setting

**確定**

- 中世風ファンタジー
- 世界は過度に荒廃していない
- 戦争そのものを中心テーマにはしない
- 怪異・超常現象が存在する
- 怪異は単なるモンスターではなく、環境の変化や自然現象との関係を持つ

**実装事実（この方針と整合している例）**

- 森の洋館では、怪異が「館の構造そのもの」を歪める（異常空間 D-01。
  同じ部屋へ戻ったはずが違う廊下に出る）。ボス撃破で構造が正常化する
- 宵待ちの村は「暗闇だから見えない」ではなく「灯りが怪異をこちらの世界へ
  引き出す」という反転構造を核にしている
- 怪異の正体はどこでも断定しない。館の主自身も分かっていない
  （`MANSION_SCENARIO.md`）

## Core Experience

**確定** — プレイヤーが各キャラクターの異なる戦闘スタイルを体験しながら、
シナリオを進める。

Chapter 1 では、章ごとに主人公が交代することでこの体験を作る
（[SCENARIOS.md](./SCENARIOS.md) 参照）。

## Core Combat Loop

**確定**（`COMBAT_DESIGN.md` §0 を正式仕様として採録）

```
敵を見る → 行動を理解する → 位置を選ぶ → タイミングよく攻撃する →
敵の体勢・向きを崩す → 有利な状況を作る
```

このループを「レベルを上げる／連打する」の上位互換にしない。
職業ごとに **何を見るか** を変える。

| 職業 | 何を見るか |
| --- | --- |
| 剣士 | 距離 |
| 戦騎士 | 身体 |
| 盗賊 | 隙間 |
| バーサーカー | 次の位置 |
| 弓師 | 現在 |
| 鷹の目 | 未来 |
| 魔法使い | 戦場 |
| 魔導士 | 戦場の変化 |

## Design Principles

**確定**

- シンプルな操作
- キャラクターごとの差別化
- 戦闘中の位置取りを重視
- スキルによる戦術的な違い
- 過剰な育成システムを Chapter 1 に持ち込まない
- 世界観とゲームシステムを一致させる

### 派生する禁止事項

**確定**

- 上位職を「同じ判定の数値違い」にしない（単純な上位互換の禁止）
- 属性相性システムを導入しない（[COMBAT.md](./COMBAT.md) 参照）
- 敵・ボスが瞬時に180度向き直らない（回転速度を持つ）

## Platform / Input

**実装事実**

- 対応入力: キーボード＋マウス / タッチ（仮想スティック） / ゲームパッド
- 保存は `localStorage`（進行 `soulforge_save_v1` / 表示設定 `soulforge_settings_v1`）
- `main` への push で GitHub Pages へ公開

## Uncertain

- 5人目「影の旅人」のプレイアブル化の正式な条件
  （実装コメントは「名もなき街道クリア後」と書くが、`名もなき街道` は
  他のどこにも定義が無い）
