## 1. 実装概要

WORK 3〜6 で1つずつ覚えてきた4つの現象を、終盤でひとつにまとめた。

```
村の奥の終点（WORK 6 の演出）
  → 扉 → 水鏡の跡
  → 村の残響（ボス）Phase 1〜3
  → 撃破
  → 散らばっていた記憶が水面へ戻る
  → 最後の記憶「……ありがとう。」
  → 夜が明ける
  → 二人の短いやりとり
  → いつもの結果画面 → 酒場
  → 酒場の棚の端に、小さな木彫りの舟が置かれている
```

**新しいゲームシステムは1つも足していない。** ボスの動き（追尾・振りかぶり・
薙ぎ・特殊行動・体幹・Break・Execution・報酬・結果画面）はすべて既存のまま。
足したのは「村で覚えた4つを場に出す層」と「結果画面の前に一拍置くこと」だけ。

### 2-1. 誰でもない

一人の怨念ではない。魚を獲ったこと、家で過ごした時間、舟を出したこと、
商いをしたこと、水門を開け閉めしたこと、誰かを待った時間 ―― 忘れられた
村の記憶が混ざったもの。

名乗りの台詞も「誰か」にしていない:

```
水面がゆっくりと盛り上がり、いくつもの輪郭が重なって、人のかたちになる。
「……まだ、誰も来ない」
「網は干したままだ」「舟は明日出す」「棚が空いている」「水門は、閉めた」
声はどれも別々の時間のもので、どれも途中で切れている。
```

**「実は○○が黒幕だった」は出さない。** 倒しても誰も帰ってこない。

### 2-2. HPで長引かせない

760 は中ボスの水門守（900）より低い。殴る回数ではなく、判断の回数で
決まるようにしてある（§9）。

## 3. Phase 1〜3

段階が進んでも **敵の性質は一切変わらない**。変わるのは組み合わせだけ
（`core/village-echo.js`）。閾値は既存ボスと同じ 65% / 30%。

| | テーマ | 分身 | 泡沫 | 写し身 | 残響 |
| --- | --- | --- | --- | --- | --- |
| Phase 1 | 記憶がまだ整理されていない | 2 | 2 | – | – |
| Phase 2 | 誰かの記憶を真似している | 2 | 3 | 1 | – |
| Phase 3 | 過去そのものが現在に重なる | 1 | 2 | 1 | 3 |

**総数は増えない**（Phase 2 の 6 体 → Phase 3 の 4 体＋残響）。増えるのは
種類であって数ではない ―― ユニットテストで固定してある。

### 3-1. 水鏡の影（WORK 3 のルールそのまま）

本体が**自分と同じ姿の分身**を出す。見た目は本体の実体を複製したもので、
色も大きさも同じ ―― 見分けるのは挙動の差（波紋・向き直り・予兆）だけ。

AIは `updateMirrorShadeAI` をそのまま使っている。当てると散る・ダメージは
入らない・散らされた分はしばらくしてから戻る、も既存のまま。

### 3-2. 泡沫の群れ（WORK 4）/ 写し身（WORK 4）

どちらも `buildDuskFoam` / `buildDuskCopyShade` をそのまま呼んでいる。
写し身は「直前の一撃を1回だけ返して WATCH に戻る」まで既存の通りで、
**「写し身を倒すのが正解」という専用ルールは作っていない。**

### 3-3. 残響（WORK 6）

Phase 3 だけ、ボスがいた場所を 2.6 秒ごとに控え、`core/warden-echo.js` の
遅れ（1.6秒）で同じ場所になぞる。水門守とまったく同じ読み方:

- **追跡しない。** 現在位置を狙って移動することもしない
- 出ている間ずっと当たるのではなく、なぞった瞬間だけ当たる
- 「今そこにいれば危険 / 離れていれば安全」

見た目だけ 1.5 倍にしてあり、**当たる範囲も同じ倍率**で広げている
（見えている通りに当たる）。

### 3-4. 観測の灯 / 幻影歩法

- **観測の灯**: 残響が始まるまでの遅れが伸びる（1.6→2.4秒）だけ。
  マーカー・正解表示・敵名表示・弱点表示は一切足していない。
  灯りが無くても遅れはあるので、他職でも見分けられる
- **幻影歩法**: ボスの `decoyKind` は `mirror`（水面に映るものを追う）。
  既存のターゲット選択（`aggroPoint`）に乗っているだけで、
  **宵待ちの村専用の Phantom Step 処理は作っていない。**
  使わなくても勝てる

## 4. 記憶解放演出

撃破した瞬間に結果画面を出さない。`onBossDefeated` に分岐を1つ足し、
**洋館の `playMansionReunion` とまったく同じ形**で一拍置いている。

```
（風が止む・画面が小さく揺れる）
  散らばっていたものが、ひとつずつ水面へ戻る（波紋＋人影を6か所へ）
  それが真ん中へ集まって、ひとつになる
  「……ありがとう。」          ← 最後の記憶。誰の声かは言わない
  （夜が明け始める）
  魔法使い「……残ったんですね」
  剣士　　「何が」
  魔法使い「……消えたわけじゃない、ということです」
  剣士　　「……残るなら、それでいい」
  → ここで初めて、いつもの結果画面
```

- **「これは○○さんの記憶です」とは言わない。** 波紋と人影だけ
- 村人は戻らない。「呪いが解けて村人が帰ってきた」にはしていない
- 魔法使いは成長を自分で説明しない。「分かりません」も使っていない ――
  分からないものを**分からないまま受け止める**言い方にしてある
- 剣士は決める側。自罰の台詞は入れていない

この分岐は純粋関数 `defersResultScreen(scenarioKey)` に切り出してあり、
**「撃破した瞬間に通常の結果処理が走らない」ことをユニットテストで固定**
している（§25）。他シナリオが false のままであることも同じテストで見ている。

## 5. 夜明け

**新しい時間管理システムは作っていない。** WORK 2 で用意してあった
`duskDawnT`（0=夜 / 1=夜明け）を 0→1 へ進めるだけ。空・霧・陽光・環境光・
リムライト・露出はすべて既存の補間がそのまま受け持つ。

約10秒かけて明けていき、その間:

- 水面の色と空が明るくなる（既存の `DUSK_DAWN` テーブル）
- 灯りが相対的に弱くなる
- 止まっていた水面に、ゆっくり波紋が戻る
- 遠くで音が一度ずつ（新しい音は足さず、既存の音を弱く使っている）

派手にしていない。「何かが終わった後の静けさ」を優先した。

## 6. 酒場の痕跡

`scenarioClears('duskvillage') > 0` のときだけ、酒場の棚の端に
**小さな木彫りの舟**が置かれる。村の住宅に転がっていた玩具の舟（WORK 4）と
同じかたち。

```
「棚の端の木彫りの舟」
  子供の手には少し大きい。舳先が何度も削り直してある。
  誰が持ち帰ったのかは、主人も覚えていないという。
  ただ、置き場所だけは決まっているらしい。
```

- **新しいセーブ項目は作っていない**（既存の `scenarioClears` を見るだけ）
- 新しい施設・必須NPC・ゲーム上の報酬は追加していない
- 世界に一つ、跡が残っただけ

酒場の主人の再訪時の台詞も、終わったあとの言い方へ変えてある:

```
あそこは何も変わらんだろう。人が戻るわけでもない。
……ただ、あんたが行ったことだけは、こっちが覚えてるよ。
```

### 12-1. `BOSS_ABILITIES` への「村の残響」の登録（§20）

既存の6ボスにはそれぞれ常時バフ（`BOSS_ABILITIES`）と proc（`BOSS_SKILLS`）が
1つずつある。宵待ちの村のボスにも同じ枠を用意するかどうかは、

- 能力名・効果・数値が正式仕様として未確定
- §20 が「無理に新能力を作る」ことを禁じている

ため、**今回は登録していない**。登録する場合は効果の方向性（例えば
「観察に関わるもの」なのか「水に関わるもの」なのか）を決めていただきたい。
決まり次第、既存構造への1行追加で足りる。
