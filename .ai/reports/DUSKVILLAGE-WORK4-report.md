## 3. 住宅 ―― 生活の痕跡と子供の記憶

### 3-1. 置いたもの

食卓を中心に、暮らしが途中で止まった形にしてある。

- **椅子が3つ、食器が4人分**（意図的な不一致。誰も言葉にしない）
- 水差しと、伏せたままの椀
- 畳んでいない衣類と、繕いかけの布
- 桶と工具
- 玩具の舟（子供用の小さいもの）

### 3-2. 子供の記憶（`playDuskChildMemory`、一度だけ）

食卓のそばで起動する。声の主は名乗らず、いつのことかも言わない。

```
（風が止む・食器の音）
  食卓の椅子のあたりに、小さい輪郭がひとつ（spawnApparition）
  「明日、船に乗せて!」
  「もう少し大きくなったらな」
  「……約束だよ」
  （輪郭が消える）
  魔法使い「……子どもの部屋ですね」
  剣士　　「分かるのか」
  魔法使い「玩具が小さいので。それと、椅子が三つで食器が四つあります」
  剣士　　「……数が合わんな」
  魔法使い「合いません。理由はまだ思いつきません」
```

**魔法使いは怪異を説明しない。** 目に入ったものから推測し、分からないことは
分からないと言う。数が合わない理由の答えは出さない ―― プレイヤーが後で
船小屋の舟と結びつける余地を残してある。

## 4. 船小屋

### 4-1. 船の記憶（`playDuskBoatMemory`、一度だけ）

```
（水の上を波紋が2つ走る）
  「……ねえ、まだ?」          ← 住宅と同じ、名前のない声
  剣士　　「……舟だ」
  魔法使い「ええ。直しかけのまま置いてあります」
  剣士　　「乗せてやるつもりだったんだろうな」
  魔法使い「……そう思います。確かめようがありませんが」
```

「この舟があの子の舟だった」とは**誰も言わない**。約束（住宅）と舟（船小屋）を
結ぶのはプレイヤーの側。

### 4-2. 環境異常 ―― 揺れが止まる舟

水面のプロップは WORK 2 から一律に位相つきで揺れている。ここでは、
船小屋の近くにいる間だけ、**小舟をひとつ選んでその1隻の位相だけ進めない**
（`p.lagHold` を時刻から差し引く）。9〜16秒に一度、1秒前後。

- 専用の演出でも、止まった時間の演出でもない ―― 既存の揺れの計算に
  「その1隻だけ時刻を進めない」を足しただけ
- 気づかなくても進行に影響しない。文字も出ない

## 5. 泡沫の群れ（`foam`）

「観察して見分ける」（水鏡の影）とは別の判断を教える敵。

| | 値 |
| --- | --- |
| 初期数 | 3 |
| 同時存在の上限 | 7 |
| 増殖間隔 | 6.5秒（交戦中のみ） |
| 1体のHP / 攻撃力 | 56 / 16（小さい） |

- **HPで硬くしていない。** 難しさは体力ではなく「増える速さ」で作る
- 上限があるので、範囲攻撃を持たない職でも必ず終わる ―― まとめて薙げる職が
  速い、という差にとどめてある
- **交戦中しか増えない。** 気づかれる前から増えていると、部屋へ入った瞬間に
  上限の群れと出会うことになる
- 上限に達している間は増殖タイマーを溜めない ―― 1体倒した瞬間にまとめて
  湧く理不尽を避けるため（`stepGrowth` がこれを保証。ユニットテスト済み）

数値はすべて `PROVISIONAL_` 接頭辞つき（実機調整前の暫定値）。

## 6. 写し身（`copy`）と Attack Snapshot

### 6-1. 何が返ってくるか

プレイヤーが出した**直前の一撃を1回だけ**返す。

```
プレイヤーが魔法弾を撃つ
  → spawnProjectileSingle の末尾で recordAttackSnapshot('magicBolt', dir, dmg)
     （記録するのは 種類・位置・向き・威力 の4つだけ）
  → 写し身が見ている間に consumeSnapshot(state, 'attackSnapshot') で取り上げる
     （取り上げた時点で記録は消える＝同じ一撃を撃ち続けない）
  → 1.25秒の溜めのあと、**いまの狙い先へ向け直して**撃つ
     （威力は 0.8 倍。装備・スフィアの育成分はそのまま返らない）
```

- **写せない攻撃は写さない。** `COPYABLE_KINDS` は現状 `['magicBolt']` のみで、
  近接・矢は `makeAttackSnapshot` が `null` を返し、写し身はその回を見送る
- 返ってくるのは種類・向き・威力の3つだけ。属性も状態異常も持たない
  （`replayPlan` の戻り値のキーをユニットテストで固定してある）
- 弾は既存の `projectiles` 配列・`hostile:true` に乗せている。**新しい弾の経路を
  作っていない。** 見た目だけプレイヤーの魔法弾に寄せてあるのは、「自分の攻撃が
  返ってきた」と読めることがこの敵の肝だから

### 6-2. 読み合い

「攻撃する → 真似される → 避ける → 攻撃する」。溜めの1.25秒のあいだに
身体が沈んで伸びるので、文字や印を出さなくても構えが見える。

## 7. 幻影歩法（魔法使い Skill 1 / MAGE-001）

### 7-1. 実装のかたち

MAGE-001 の分析どおり、**差し替えたのは①接近・向き直り ②攻撃を始める判断の
2つだけ**。命中判定は今までどおり `state.pos` を見る。

```js
// 07-ai-combat.js
function aggroPoint(en){   // 「いま向かっている先」
  const kind = en.decoyKind || en.atkType;
  return aggroTarget(en.group.position, state.pos, state.decoys, {pull: decoyPullFor(kind)});
}
// 各AI
const aim = aggroPoint(en);                       // 向かう先（幻影かもしれない）
const distToPlayer = state.pos.distanceTo(...);   // 索敵と命中は必ず本物で測る
```

この形にしたので、**「デコイが攻撃を受け止める」処理を新設していない** ――
敵は幻影へ向かって攻撃し、本物はそこにいないので自然に空振りする。
逆に、命中判定まで `aim` で測ると本人が無敵になる。ここが唯一の危険箇所なので、
コード側にもコメントで明記してある。

### 7-2. 必須の攻略法にしない歯止め

敵ごとに釣られやすさが違う（`DECOY_PULL`）。

| 敵 | 釣られやすさ |
| --- | --- |
| 水鏡の影 | 1.0 |
| 突進型 | 0.8 |
| 泡沫 | 0.7 |
| 写し身 | 0.35（本人を見ているので、至近に置かないと逸れない） |
| 未登録 | 1.0（既定） |

全員が必ず釣られるようにすると、幻影歩法が必須の攻略法になってしまう。
**使わなくても勝てて、使うと有利**の幅に収めてある。ダメージは持たない
（`baseMult: 0`）。

### 7-3. 見た目

`buildPlayer()` は呼んでいない ―― `player` / `playerMixerParts` は連結スコープの
共有変数で、2回目の `buildPlayer()` はプレイヤー本体のリグ参照を壊す
（ARCHITECTURE.md）。薄い輪郭（コーン＋球）で足りる。消える間際に薄くなるので、
引きつけが切れる瞬間が読める。

## 8. 観測の灯との連携

写し身の**写しに入る前の溜めが伸びる**（1.25秒 → 1.81秒）、沈み込みが深くなる。
届く距離の判定は WORK 3 の `observeReaches` をそのまま使っている。

- 答えを表示しない。文字も印もマーカーも出さない
- **灯りが無くても溜めは見える** ―― 沈み込みは灯り無しでも起きる。
  他職が詰まないことをここで担保している
- 必須ではない（WORK 3 と同じ方針）

## 12. 設計上の判断・残課題

### 12-1. 実装中に見つけて直した不具合（2件）

いずれも WORK 4 で足したものが原因なので、この WORK の中で直してある。

1. **幻影歩法がスキル選択の一覧に出なかった。** Skill 1 の一覧は
   `['dash','retreat','spin','barrier']` という固定の並びに、スフィア盤や
   転身で解放されるものを足す形になっていた。`phantom` はどちらでもない
   （最初から選べる）ので、定義しただけでは画面に出ず、装備できなかった。
   並びに `phantom` を足し、その職に無いキーは飛ばすガードを入れた
   （他の3職では今までどおり4種のまま）。
2. **入れる建物の中が見えなかった**（§9-2）。WORK 4 の生活の痕跡がまるごと
   画面に出ていなかった。WORK 3 の魚屋も同じ状態だった。

### 12-2. `state.pos` を直接読む敵が多数残っている（設計判断）

WORK 4 で `aggroPoint` を通すようにしたのは、幻影が意味を持つ4種
（水鏡の影・泡沫・写し身、および `DECOY_PULL` に載る突進型）だけ。
他の敵AIは今までどおり `state.pos` を直接読む（既定の `pull` は 1 なので、
載せ替えれば釣られるようになる）。

MAGE-001 の分析どおり、既存AIの一括書き換えはしていない ―― 82箇所ある
`state.pos` 参照のうち、命中判定に関わるものを取り違えると無敵バグになるため、
**1体ずつ確認しながら載せ替える**方針を取っている。

### 12-3. 写せるのは魔法弾だけ（暫定）

`COPYABLE_KINDS` は現状 `['magicBolt']`。近接・矢を写すには、それぞれ
「敵が出す近接判定」「敵が出す矢」の再生側が要る。写せない攻撃を無理に
近い形へ丸めると「自分の攻撃が返ってきた」という読みが崩れるので、
**再現できないものは静かに見送る**ことにしてある。

剣士・弓使い・盗賊で写し身と戦っても、写しが起きないだけで戦闘は成立する
（写し身は通常の接近戦をする）。

### 12-4. 数値はすべて暫定

`PROVISIONAL_` がついているもの: 幻影の寿命(5.0秒)と引きつけ距離(11.0)、
泡沫の初期数(3)・上限(7)・増殖間隔(6.5秒)・湧く距離(2.6)、
写しの遅延(1.25秒)・威力倍率(0.8)。実機での調整待ち。

  決めるものなので暫定のまま置いてある
