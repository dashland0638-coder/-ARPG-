対象: **Chapter 1 の最後**（道 → 5人目 → Chapter 1 終了 → Chapter 2 への境界）

## 0. 結論（先に）

Chapter 1 が最後まで一本につながった。

```
洋館 → 酒場 → 宵待ちの村 → 酒場 → 幽霊船 → 酒場 → 時計塔 → 酒場
     → 道（道標 → 先を歩く人影 → 休憩所で影の旅人と出会う
            → 影の旅人が主人公・盗賊が支援 → 戦闘 → 丘）
     → 酒場（全員が揃う、最後の会話） → Chapter 2 の入口
```

- 酒場から出られるのは **いま進めているシナリオひとつだけ**（再訪なし・寄り道なし）
- 死亡 → 酒場 → **同じシナリオをもう一度**（主人公・支援・進行は巻き戻らない）
- `state.chapter` などの Chapter runtime state は今回も **0**。**セーブの項目も増やしていない**

### 既存仕様との整合

> 「このキャラは『ある日いきなり仲間になる』のではなく、最初からずっと酒場にいた人物が、

> 「プレイアブル化（名もなき街道クリア後）は別途、行方不明者の捜索イベントを起点に追って実装する」

### Boss Ability（§25：設計の確認のみ）

`BOSS_ABILITIES`（`12-progression-ui.js`）は **bossKey で引く、クラスに依存しない常時バフ**で、
`state.learnedBossAbilities` / `equippedBossAbilities` として主人公が交代しても共有される。
影の旅人も他の4人と同じく装着できる。「5人目だけが Boss Ability を取得できる」という特殊性は
**まだ実装されておらず、今回も実装していない**。既存の仕組みには手を入れていないので、壊してもいない。

## 5. 5人目 Playable 化

`CLASSES.wanderer`（`01-character-creation.js`）を追加した。

```js
wanderer:{ key:'wanderer', name:'影の旅人', icon:'◐', kit:'warrior', hidden:true,
           color:0x1a1622, trim:0x8a5ad6, ...基礎ステータス..., ult:{ name:'影送り', ... } }
```

**専用の戦闘システムは作っていない**（§23）。操作できるようにするために、戦闘の骨格
（通常攻撃・回避・Skill・必殺技の型・武器の持ち方・リグ）は既存の職から **借りている**（`kit`）。

- `recomputeStats()` が「借りた職の値 ＋ 自前の名前・色・基礎ステータス・必殺技名」を重ね、
  `state.classDef.key` だけは借りた職のままにする ―― 上位職（#9）が key を変えないのと同じ理由で、
  `WEAPON_TYPES` / `STANCE` / `CLIPS` / リグなど基礎職キーに紐づく既存の仕組みを**そのまま動かす**ため
- 自前で持つのは **名前・見た目の色（酒場の隅の姿と同じ黒と紫）・基礎ステータス・必殺技の名前**だけ
- `hidden:true` でテストモードの職業／同行ゲスト一覧には出さない（本編の進行でだけ現れる）
- 借りる職は **暫定で剣**（いちばん素直な近接の型）→ 要判断事項 16-1

`CHAPTER_CAST[5]` は `classKey:null` → `'wanderer'`、`dungeonKey:null` → `'road'` にした（**意図した変更**）。
`chapter:` フィールドは変えていない（§38、下の §8 も参照）。

### 交代の場面

主人公の交代は、休憩所の一幕の中で起きる（§22「Chapter 1 最後: Playable 5人目 / Support 盗賊」）。

- 道へ出るときは **盗賊＋弓師**（5人目は道の途中で見つかるので）
- 出会いの一幕の終わりにフェードを挟んで交代 → 影の旅人が主人公、盗賊が支援AI、弓師は休憩所に残って来た道を見張る
- 交代そのものは WORK 10 の酒場の交代と **同じ関数**（`switchProtagonist`、14-hud-boot.js）。
  持ち替えるのはクラス・武器・Skill 1 の選択だけで、レベル・所持品・防具は引き継ぐ

`core/chapter1-progress.js` では、これを「その段の主人公とシナリオの途中で出会う」（`MET_INSIDE = ['road']`）
として表した。道を終えるまでは前の段（盗賊＋弓師）の顔ぶれで数え、出会いの一幕だけが
`castAfterMeeting(5)`（影の旅人＋盗賊）を使う。

## 9. 死亡・再開

```
死亡 → 「酒場へ戻る」 → returnToTown(true) → 酒場
     → 出撃画面に出るのは、いま進めているシナリオひとつだけ
     → 主人公・支援・Skill 2・加入・クリア済みは何も変わらない
```

- 死亡では `scenarioClears` が増えないので、`nextScenario()` の答えは変わらない ―― 「現在のシナリオ」を
  新しく覚えておく必要が無い（§35「既存値を使う」）
- 酒場に戻ったとき「〇〇へ、もう一度。店主に声をかければ出られる」とだけ出す
- **例外（道の途中）**：影の旅人と出会ったあとに死亡・撤退すると、酒場で **盗賊＋弓師へ戻り**、
  道はもう一度最初から（出会いも、もう一度）。交代は道の中の一幕で、進行（scenarioClears）には
  まだ記録されていないため。加入の一幕は出さない（`isForwardSwitch` で「戻るだけ」と判定）→ 要判断事項 16-2

## 10. 再訪不可

`core/chapter1-progress.js` の `offeredScenarios(clears)` が唯一の答え。

| 状態 | 出撃画面に出るもの |
| --- | --- |
| Chapter 1 の途中 | **いま進めているシナリオ1枚だけ** |

- 章の外（神殿・水路・温室）も **出ない**。レベルが足りていても出ない（WORK 10 では出ていた ―― 仕様変更）

- 画面の見出しも「出撃 - シナリオ選択」→「出撃 - 次の行き先」
