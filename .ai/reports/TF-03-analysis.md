## 6. 原因の確定（2026-10-09、#65 の記録から）

#65 で入れた記録が、PR #66 の CI で2回とも失敗を捉えた（どちらも #66 の変更とは無関係。#66 は `.md` のみ）。

| テスト | 記録 | 読み取れること |
| --- | --- | --- |
| :263（safe-area） | プロンプト left **452** / top 177〜212。`#joy-zone` 47〜**452.109** / top 210.609。画面 844×390・visual viewport 844×390×1。直前の書き換えは 433 → 436 → … → 450 → 452（対象に追従して少しずつ右へ） | 画面の幅は正常。**§3 の「画面幅が違う」仮説は否定**。対象の点が 452.3 のような端数の位置に来ると、重なりの判定（丸める前）は「重ならない」で、返す値の `Math.round` で 452 になり、0.109px 内側に入る。#41 / #64 の 405 対 405.109 も同じ形 |
| :296 | 押す前に測った left 254 → 押している間 253。押している間の書き換えは全て 253（カメラが回っても変わらない） | 押している間は止まっている（ゲームは仕様どおり）。1px は押す直前の1フレームに起きた丸めの変化で、テストが押す前の位置を基準にしていたため |

### 原因
1. **`placeAnchoredPrompt`（`src/core/combat-prompt-layout.js`）が、重なりを丸める前の位置で判定し、丸めた位置を返していた**。`#joy-zone` の大きさは %指定（幅 48%・高さ 46%）で端数が出るので、端から 0.5px 未満の位置は丸めで内側へ入る。実際の UI の不具合（0.1px の重なり。見た目には分からないが、タッチの判定の境界ではありうる）。
2. 同じ種類の食い違い: 置く幅に `offsetWidth`（176、整数に切り捨て）を使っていて、実際の幅（176.297）より小さい。右側の矩形（Action ボタン）に対して同じ 0.3px の食い込みがありうる（CI では未観測）。
3. :296 はテストの測り方（押す前の位置を基準にしていた）。ゲームの不具合ではない。

### 修正（最小）
- `placeAnchoredPrompt`: 重なりを **丸めた位置** で判定する（1行）
- `placePromptOverWorld`: 置く幅・高さを実際の大きさの切り上げにする（`Math.max(offsetWidth, ceil(rect.width))`）
- :296: 基準を **押した瞬間の位置** にする（許容 1px 未満は変えない。待ち時間・リトライの追加なし）
- unit: CI と同じ矩形（405.109 / 452.109、高さ 210.609）で、対象の点を 0.05px 刻みで動かしても重ならないこと（修正前は失敗することを確認）

ゲームの仕様・凍結対象には触れない（表示位置の 1px 未満の丸めだけ）。
