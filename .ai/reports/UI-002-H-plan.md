**Goal**: 会話・通知・結果・戦闘不能・確認を、HUD（C2）と UI-002-F と同じ視覚言語にそろえる。会話は台詞と話者の識別、戦闘中の通知は短時間での認識、結果は「何が起きて何を得たか」を優先する。ゲームの進行・台詞・報酬・表示条件は変えない。

## 3. 画面ごとの設計案

### 3-1. 会話（「ページ」）
```
            ┌[ 剣士 ]────────────────────────────────┐   ← 話者名は上辺の「しおり」（名札）
            │ ようやく、噂に聞いていた街に辿り着いた。          │   ← 本文 15px（現 14.5px）、行間 1.8
            │                                            ▼ │   ← 送りの印（右下）
            └──────────────────────────────────────┘
```
- パネル: プレート（単色の面は不透明に近い `--ui-plate-bg`。世界が透けすぎない）。位置・幅は現状どおり（下寄せ・`min(640px,92vw)`）
- 話者名: 上辺に重なる小さなプレート（名札）。ember の文字、Cinzel / Noto Serif JP。名前が変わる掛け合いでも位置が動かない
- 本文の大きさは 15px（DECISION ではなく F-D3 の下限以上の範囲で Agent が決める。実機で要確認）
- 844×390: 現状 143px の高さで下 45% を覆う → 余白を詰め、`max-height` を画面の 40% 程度に（スクロールは本文だけ）
- 肖像は作らない（仕組みが無い = 未実装機能）

### 3-2. 確認（「封をした書付」）
- プレート（380px のまま）、見出しは碑文（F の `.menu-head` と同じ罫＋菱形）
- ボタン: OK = primary プレート、キャンセル = 通常プレート。危険な操作（タイトルへ・撤退・上書き）でも色は変えない（呼び出し側の区別が無いため。追加するとロジックの変更）
- ぼかしをやめる。z 120 は維持

### 3-3. 結果（「戦果の記録」）
```
┌───────────────────────────────┐
│            VICTORY                 │  ← 碑文の見出し（文言は維持）
│      屋敷の主を打ち倒した。…         │
│ ┌──────────────────────────┐ │
│ │ 🪙 ゴールド               +48 │ │  ← 戦果の行はプレートの中の表（点線ではなく行の面）
│ │ 🗝 主の袖飾り              ×1 │ │
│ └──────────────────────────┘ │
│        [ 街に戻る ]                  │  ← primary プレート 36px 以上
└───────────────────────────────┘
```
- 表示条件・行の中身は変えない（本編はゴールドと品だけ）
- テストモード専用の 3 択報酬・ステ振りは同じ部品で崩れない程度に（文字を 11px 以上へ。再設計はしない）
- 844×390: 現状 290px で収まる。テストモードで行が増えた時は箱の中だけスクロール

### 3-4. 戦闘不能（「静かな頁」）
- 結果と同じ部品。見出しの色（`#c9576a`）と罰金行（`#e0a04a`）を class に移す（値は同じ。token に同じ値が無いため。新しい色ではない）
- 文言・挙動（罰金・ボスの初期化・帰還）は変えない

### 3-5. 通知（§4 の推奨案 B の場合）
- 中央トースト: 文字の下に小さなプレート（matte・輪郭・内縁）を敷く。発光の影をやめる。大きさ 15px は維持
- 左下ログ: 半透明 0.6 の pill → プレート（不透明に近い面）。11.5px → 12px（F-D3 の原則）。位置・行数（D6）は維持
- 重要度は既存の色の直書きをそのまま（呼び出し 120 か所を変えない）。形の区別は作らない（アイコンは E）

## 4. 通知の扱い（比較）

前提（FACT）: HD-D17 / WI-D5 で「種類ごとに 1 つの表示先」へ統合済み（中央トースト = 即時の反応、左下ログ = 記録）。重複 0。

| 観点 | **A** 共通コンポーネントに集約 | **B** 用途別の 2 系統を維持し、見た目と優先順位を統一（推奨） | **C** 経路も見た目もほぼ維持し、重なりだけ改善 |
| --- | --- | --- | --- |
| 内容 | トーストとログを 1 つの部品・1 つの場所へ（重要度で見た目を変える） | D5 の表を正本のまま、両方を同じプレート言語に。トーストの段数に上限、寿命と可視時間を一致 | トーストの段数の上限だけ |
| 読みやすさ | 1 か所に集まるが、長い物語の文と短い戦闘の反応が同じ場所で競合 | 役割ごとの場所を保ち、見た目だけ統一 | 現状のまま（プレートと不一致） |
| 戦闘中の見落とし | 物語の文に戦闘の反応が埋もれる危険（INFERENCE） | 中央 = 即時の反応のまま | 現状のまま |
| 実装コスト | 大（120＋74 の呼び出し・D5 の表の見直し） | 小〜中（CSS ＋ `layoutToasts` の上限・寿命の定数） | 小 |
| 既存テスト | `watchNotifications`・17 spec の読み先が変わる | 変わらない（class・表示先を維持） | 変わらない |
| 回帰リスク | 高（D5 の Human 決定の再設計になる） | 低 | 低 |
| Human 決定との関係 | **HD-D17 / WI-D5 の見直し**になる | HD-D17 と整合 | 整合 |

**推奨: B**。理由: 表示先の分け方は Human が D で決めており、H の目的（視覚の統一）と衝突しない。A は D5 を作り直すことになり、H の範囲を越える。
通知履歴は作らない（Undecided）。
