# CHAPTER 1 Experience Plan — 第一章の体験品質の改修計画

Date: 2026-10-13
Base: `origin/main` `7020e4d`
監査: `.ai/reports/CHAPTER-1-experience-audit.md`（以下「監査」）
Task: `.ai/tasks/CH1-EXP.md`（Work Item の Status と Approval の正本）

## 0. 方針

- 1 つの Work Item = 1 本の作業ブランチ = 1 つの PR。変更の範囲を小さく保つ。
- 既存の仕組みを使う。新しい演出基盤・新しいアニメーション基盤は作らない。
  - 演出: `playCutscene` / `cutsceneLine`
  - 歩き方: `updateLocomotion` と、その表（`BUILD` / `STANCE_RELAXED` / `RELAXED_WALK_*`）
  - 時間帯: `DUSK_BANDS` と補間
  - 交代: `switchProtagonist` / `queueChapter1JoinScene`
- 次の制約は全 Work Item で共通:
  - 第一章に無い要素を足さない（Level / XP / スフィア / パッシブ / Skill 3 / フルクラフト / 鑑定 / 強化）。
  - 交代の順番、進行の条件、セーブの形式、敵・ボスの数値を変えない。
  - `basefile.html` を変えない。legacy の連結構成を ES Module にしない。
- テストモードだけの機能を本編に出さない。開発用の入口は `?dev=1` の中に閉じる。
- 完成の判定は、E2E の PASS に加えて、Human の iPhone 実機の通しプレイ（CQ-01）。
  - 見た目の項目（腕振り・日没・登場の演出）は、Work Item ごとに Human の目視（V-1）を Acceptance に含める。

### X-2 宵待ちの村の演出テンポ（要件 C）

- **Goal**: 村のイベントで「止まった」と感じる時間をなくす。見せたい演出の間は残す。
- **Scope**（監査 §3.2 のイベントごと）:
  1. **台詞の間の無言の間を詰める**
     - 対象: 魚屋・住宅・船小屋・商店街の記憶。記憶の声の後、会話欄を消してから二人が話し出すまでの 0.8〜1.2 秒。
     - 会話欄を消さずに次の行へ続けるか、間を 0.3 秒程度にする。
     - 閃き → 水門前の継ぎ目（0.6 / 0.8 秒）も同じ。
  2. **前置きの詰め方を分ける**
     - 歩く・振り向くだけの前置きは、今どおり 0.8 秒以内に詰める。
     - 「見せ場」の手順は詰めない。対象:
       - ボスの手前で記憶が集まる。
       - 撃破後に記憶が戻る。
       - 水門守のレバーと鎖が動く。
     - 手順に `keep:true` のような印を付け、`playCutscene` の詰めの計算から外す（既存の関数への小さな追加。新しい基盤は作らない）。
     - 見せ場の長さはそのままにし、プレイヤーが送れる台詞が出るまでの最長を決める。目安: 見せ場の合計 3 秒以内。超える分は間を詰める。
  3. **入口の場面**: 主人公が足を動かさずに滑る `walkTo` を、X-4 の歩き方でつなぐ（X-4 の後）。
  4. **終わりの向き直り**: 0.7 秒は残す。カメラが戻るのに要る。
- **Out of Scope**:
  - イベントの数・場所・台詞・発生条件・順序。
  - 記憶のイベントを「止めない演出」（村の奥の記憶と同じ、ログだけの形）へ変えること。体験の設計が変わるので、やるなら Human の判断。
  - 他のシナリオの演出。X-2 で直した後、同じ印を他のシナリオへ広げるのは別の Work Item。
- **Acceptance Criteria**:
  1. 監査 §3.2 の「台詞の間の無言の間」が 0.3 秒以下になる。
  2. 見せ場の 3 演出（ボスの手前・撃破後・水門守の登場）で、印を付けた手順が詰められない。
  3. 各イベントは出撃 1 回につき 1 回、順序も今どおり。演出中に別の演出・操作が割り込まない。
  4. 既存の unit・E2E（`chapter1-dusk-basics`・`chapter1-skill2` ほか）が通る。
- **Test Plan**:
  - unit（新規）: 詰めの計算を `core/` の純粋関数へ切り出す。
    - 「歩く・振り向く手順だけ詰め、印の付いた手順は詰めない」を数値で固定する。
    - 今の `stepShowsLine` / `leadSpeed` の計算と同じ入力で比べる。
  - unit: 村の 4 つの記憶で、声の行と二人の会話の間の待ちが上限以下であることを、演出の手順から読む。
  - E2E: `chapter1-dusk-basics.spec.js` の入口の一幕。台詞が送りで進み、終わると操作が戻ることは既にある。会話の間に「台詞なしで操作もできない区間」が無いことを足す。
  - 実機（Human）: 村を通して「止まった」と感じる所が無いか（V-1）。
- **Dependencies**: X-4（無くても進められる）。
- **Human Decision**: 無し。

### X-3 非戦闘の歩行の腕振り（要件 E）

- **Goal**: 歩くときに腕が体の前に張り付かず、左右交互に自然に振れる。止まると休めの姿勢へ戻る。
- **Scope**（共通の式と表だけ。職ごとに別の実装は作らない）:
  1. **腕振りの量**
     - 対象: `RELAXED_WALK_ARM_SWING`（`core/relaxed-idle.js:178`）と、`13-update-loop.js:1222` の `0.62` の係数（非戦闘側だけ）。
     - 歩く速さで肩の振れが前後 ±18〜25° になるように上げる。
     - 戦闘態勢（walkW = 1）の値は変えない。
  2. **歩くときの腕の基準姿勢**
     - 休めの姿勢の肩の前後と肘の曲げは、止まっているときの値。歩くときは肩を体の横（前後 0° 付近）、肘の曲げを浅くする。
     - `locomotionArmBase` に「歩行中の休め」を 1 段足すか、`RELAXED_WALK_UPPER` と同じ倍率の表を足す。
  3. **肘の追従**: 腕を後ろへ振ったときに肘を伸ばし、前で軽く曲げる。今の `0.5·swing` の符号と量を見直す。
  4. **胴の上下動・ひねり**
     - 今の `RELAXED_WALK_UPPER`（run 0.35）を、腕振りと釣り合う量へ。
     - 上下動の周期は歩幅の位相（`strideT`）のまま。
- **Out of Scope**:
  - 脚の振り・歩調の係数 2.7・移動速度・入力（CHARACTER-VIS-001 D-3 で据え置いた所）。
  - 攻撃クリップ・構え（`STANCE`）・武器の握り・収納。
  - 支援 AI と NPC の歩き方。
- **Acceptance Criteria**:
  1. 非戦闘で歩くと、4 職とも肩の前後の振れが ±18° 以上になる（モーションパネルの値、または unit の式で確かめる）。
  2. 止まると 0.5 秒前後で休めの姿勢へ戻る（今の `relaxStopBlend` の速さのまま）。
  3. 戦闘態勢の歩行・攻撃・回避・ジャンプの姿勢が変わらない。walkW = 1 で従来の値に一致する（`relaxed-idle.test.js` の既存の確認）。
  4. 上位 4 職・影の旅人でも、腕が胴や武器にめり込まない（撮影して Human が確認）。
  5. iPhone の横画面のカメラ距離で、腕振りが見て分かる（Human V-1）。
- **Test Plan**:
  - unit: `relaxed-idle.test.js` に、非戦闘の腕の振れ幅（式）が下限以上であること・walkW = 1 で従来値に一致することを足す。
  - E2E: `character-motion.spec.js` の撮影に、非戦闘の歩行のショットを 4 職ぶん足す。値は数値で、見た目は Human。
  - build / unit / `character-*` の E2E。
- **Dependencies**: 無し。
- **Human Decision**: 無し。ただし Acceptance 5 の目視は Human。

### X-4 演出中も主人公・同行者を止めない（要件 C・E の共通の原因）

- **Goal**: 演出中も、主人公の呼吸・待機の揺れが止まらない。演出で歩かせるときは足が動く。
- **Scope**:
  1. 演出中のループ（`14-hud-boot.js:1388`）で、主人公の見た目のアニメーションだけを進める。
     - `updateLocomotion` を「入力なし・移動量は `walkTo` の速さ」で呼ぶ。
     - 攻撃・スキル・カメラの戦闘処理は呼ばない。
  2. 村の `stepDuskGuestWalk`（`14-dungeon-duskvillage.js:824`）で同行者を歩かせる間も、支援 AI が普段歩くときの上下の揺れ（`updateGuestCompanion` の `bobT`、`08-loot-equipment.js:1133-1134`）を付ける。
     - 支援 AI には、もともと脚の動きが無い（揺れだけ）。脚を付けるのは支援 AI の見た目の改修（古い監査 E-3）の範囲で、X-4 では扱わない。
- **Out of Scope**:
  - 演出の時間・順序・台詞。
  - 支援 AI の見た目・戦闘（古い監査 E-3）。
- **Acceptance Criteria**:
  1. 演出中、主人公の胴の呼吸・待機の揺れが止まらない（モーションパネルの値が変わり続ける）。
  2. `walkTo` で動く間、主人公の脚が歩く。演出で歩く同行者も、普段と同じ上下の揺れで動く。
  3. 演出の後、操作に戻った瞬間に姿勢が跳ばない。
  4. 洋館の分離・再会、村、時計塔の崩壊・跳躍、道の出会いの演出が、今どおり最後まで進む。
- **Test Plan**:
  - E2E: 村の入口の一幕の最中に、モーションパネルの値が 2 回読んで変わっていることを確かめる。
  - 既存の演出の E2E（`mansion-escort`・`chapter1-dusk-basics`・`chapter1-tower-to-road`・`road`）を全部通す。
- **Dependencies**: X-3（同じ式を使う。X-3 が無くても動くが、見た目は X-3 の後で確かめる）。
- **Human Decision**: 無し。

- **Scope**（推奨案 = EX-1 の A）:
  1. `returnToTownNow()` の順番を変える。
     - 暗転の最中は、帰ってきた主人公のまま酒場に立たせる。
     - 交代は「交代の場面の予約」だけにする。

  2. 酒場が描かれたら（今の `joinSceneReady`）、次の順で 1 つの演出として流す。
     1. 帰還の会話（1〜3 行）。
     2. 次の主人公の姿（`buildCastFigure`）が席から歩み寄る。

        - 姿の位置へ主人公のリグを置き、姿を消す。
        - 前の主人公は支援 AI として隣に残る（今の顔ぶれと同じ）。
