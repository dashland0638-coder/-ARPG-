# CH1-COMP W1-2 — 弓師の歩行姿勢の計測（報告）

基準: `main` `04d2ea7`。branch `claude/w1-2-archer-walk-posture`。Work Item: [`../tasks/CH1-COMP-W12.md`](../tasks/CH1-COMP-W12.md)。

## 1. 結論

**操作して歩くとき（探索中）は解消している（判断 A）。ゲームのコードは変えない。**

- 歩行中の弓師と剣士の姿勢の差は、同じ速さでは 0.15° 以下。しかも弓師の方が 0.14° 小さい（体格の `strideAmp` による。§3）。
- 操作して歩いている間、視線（Look Rig）が体幹へ足す傾きは 0°（W1-1 が効いている）。
- W1-1 の前は、弓師だけ歩行中の体幹の前傾が約 17°（剣士は約 3°）あった。今は弓師も約 3°。
- **残っているもの（今回の対象外）**: 演出・会話の最中の徒歩（自動の階段・演出の歩み寄りなど）と、戦闘態勢での移動では、視線が体幹に足す傾きが積み上がる仕組みが今のコードにも残っている（§4）。原因は歩行の係数ではなく Look Rig なので、別の Work Item を提案する。

## 2. 計測の方法

- 実物のゲーム（開発サーバー、Chromium）。テストの間だけ、連結済みのソースの末尾に参照を足して、リグの回転を毎フレーム読む（ゲームのコードは変えない。MUSIC-BGM-REGRESSION-001 の E2E と同じ方法）。
- 同じ条件
  - 場所: 酒場の中央（平らな床）から、カメラから見た前方（W。ワールドでは約 45° の向き）へ。
  - カメラ: 自動追従を切った固定の角度。
  - 入力: W を押し続ける。ゲーム内で約 3 秒（自動テストはゲーム内の時間が実時間の 1/4）。
  - 歩き出しの 4 割を捨て、定常の歩行（非戦闘・構えなし・振りなし）だけを使う。1 件あたり 50〜56 フレーム（止まっているときの計測は 48〜49）。
- セーブ: 剣士＝新規の進行（支援なし）、弓師＝宵待ちの村のクリア後（支援は魔法使い）。どちらもレベル 1。
- 速さ: 職業の速さ（剣士 5.0・弓師 5.6 m/s）のままと、同じ速さ（弓師を 5.0、剣士を 5.6 にした組）の両方。
- 計測項目（度）
  - 体幹の pitch（`waist.rotation.x`。+ が前傾）。
  - 視線の寄与（Look Rig の `waistPitch`）。
  - 頭の pitch（`headLookPivot.rotation.x`）。
  - 全身の前傾（X 成分）（`-player.rotation.x`）。カメラが 45° なので傾きの大きさの cos45° 倍（約 0.71 倍）が出る。職業どうしの比較には影響しない。
  - 上半身の前傾（ワールド）: 腰から頭のピボットへのベクトルの、進行方向への傾き。
- W1-1 の前: `0079dc2` の 1 つ前の main を別の作業ツリーに取り出し、同じ方法で計測（当時は Look Rig の値を外から読めないので、視線の寄与は「―」）。

## 3. 結果（定常の歩行、平均。かっこ内は最小〜最大）

**現在（W1-1 の後）**

| 条件 | 体幹の pitch | 視線の寄与 | 頭の pitch | 全身の前傾（X 成分） | 上半身の前傾 |
| --- | --- | --- | --- | --- | --- |
| 剣士（5.0） | 3.03（2.76〜3.03） | 0 | 0 | 1.06 | 2.17 |
| 弓師（5.6） | 3.09（2.86〜3.10） | 0 | 0 | 1.18 | 2.19 |
| 弓師を 5.0 に | 2.89（2.64〜2.91） | 0 | 0 | 1.06 | 2.10 |
| 剣士を 5.6 に | 3.23（2.96〜3.24） | 0 | 0 | 1.18 | 2.26 |

- 同じ速さでの差（弓師 − 剣士）: 体幹 -0.14°（5.0）／-0.14°（5.6）、全身 0.00°、上半身 -0.07°（どちらの速さでも）。弓師の方が前傾が強いということは無い。
- 差の内訳（コードの式で検算し、実測と合う）
  - 体幹の歩行の前傾は `0.02 + run×0.35×0.11` rad で、`run` は歩幅の振れ `swing` から決まり、`swing` に体格の `strideAmp`（剣士 1.00・弓師 0.93、`05-rendering-rig.js` の `BUILD`）が掛かる。式からは 5.0 m/s で剣士 3.03°・弓師 2.90°（実測 3.03 / 2.89）。
  - 同じ速さでの -0.14° は、この `strideAmp` の差による。弓師の前傾を**弱める**向きなので、調整しない判断は変わらない。
  - 職業の速さのままの差（体幹 +0.06°）は、速さの分（約 +0.20°）と `strideAmp` の分（-0.14°）の合計。全身の前傾の差（+0.12°）は速さの分だけ。

**W1-1 の前（参考）**

| 条件 | 体幹の pitch | 全身の前傾 | 上半身の前傾 |
| --- | --- | --- | --- |
| 剣士（5.0、支援なし） | 3.02 | 1.05 | 2.16 |
| 弓師（5.6、支援あり） | **17.08**（15.55〜18.97） | 1.18 | **16.22** |
| 弓師を 5.0 に | **17.58** | 1.06 | **16.80** |
| 剣士を 5.6 に | 3.23 | 1.18 | 2.26 |

- 当時の差は、支援（後ろの仲間）を見続ける視線から来ていた（全身の前傾は同じで、体幹だけが大きい）。
- 仕組み（推定。コードから）: Look Rig は毎フレーム体幹へ `waist.rotation.x -= look.waistPitch` で足し込み（`13-update-loop.js` の視線の書き込み）、次のフレームの歩行の補間 `+= (pitch - x)×dt×8` はその足し込んだ値から始まる。そのため定常の値は「歩行の前傾 + a/k」になる（a = 視線の寄与、弓師 4.0°。k = 1 フレームの補間の割合 dt×8）。
  - 計測は約 7fps・ゲーム内の時間 1/4 で dt≈0.035、k≈0.28 なので、3° + 4°/0.28 ≈ 17° で実測と合う。監査の見積もり 4.0° はこの a。
  - k はフレームレートで変わる。当時の 17° はテストのフレームレートでの値で、iPhone の 60fps（k≈0.13）では約 33°（3° + 4°/0.13）と、もっと大きかった可能性がある。
- W1-1 で操作中の歩行では仲間を見なくなり（a = 0）、この差は消えた。

## 4. 歩行以外で見えたこと（今回は変えない）

**演出中の徒歩・戦闘態勢の移動（残っている積み上がり。別の Work Item を提案）**
- §3 の積み上がりの仕組み（視線の足し込み → 次のフレームの補間の起点）は、今のコードにも残っている。操作中の歩行では視線の寄与が 0 なので起きない。
- 演出・会話の最中（`dialogueActive`）の徒歩（自動の階段・演出の歩み寄りなど、`updateBodyWhileScripted` → `updateLocomotion`）では、W1-1 の規則で歩きながら仲間を見るので、支援がいると体幹が強く前へ倒れうる（弓師・魔法使い・盗賊。剣士は第一章では支援がいない）。
- 戦闘態勢で見えている敵がいる間の移動でも、構えの重みが 1 未満の間は少し積み上がる。
- 原因は歩行の係数ではなく Look Rig なので、W1-2 では変えない。対策の例: 体幹へ足し込む前の値を補間の起点にする（Look Rig の足し込みを補間の外に出す）。

**止まっているとき（仕様どおり）**
- 止まっているとき、弓師は隣の支援を見る（W1-1 で残した仕様）。頭 5.06°・視線の寄与 -4.0°（体幹を前へ 4°）・体幹 4.70°・上半身 4.92°。
- 剣士は第一章で支援がいないので 0.98°（比べられる条件ではない）。
- 止まっているときの視線は W1-1 で残すと決めた動き（`lookTargetKind` の規則）。止まっている間は休めの姿勢が体幹を絶対値で書くので、積み上がりも起きない（4.70° ≈ 姿勢 + 4°）。
