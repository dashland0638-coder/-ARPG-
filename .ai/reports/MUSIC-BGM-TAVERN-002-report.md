## 2. 継ぎ目（iPhone で途切れる）の原因

この環境では iPhone の再生を再現できない。001 の鳴らし方には、iPhone で途切れうる所が 3 つあった。

1. `AudioBufferSourceNode` の `loopStart` / `loopEnd` と再生開始位置（offset）に頼っていた。WebKit がこれをサンプル単位でなく丸めて扱うと、継ぎ目がずれる。
2. MP3 の先頭の遅れ（576 + 詰め物）をデコーダが取り除くかどうかに頼っていた（Chromium は取り除く）。
3. 1 周 47.766984 秒は 48kHz でサンプル数が割り切れない。iPhone の AudioContext は 48kHz のことが多い。

**対処**（3 つとも頼らない形）

- 1 周を 1/300 秒単位に丸めた（47.766667 秒 = 44.1kHz で 2,106,510、48kHz で 2,292,800 サンプル）。
- デコード後に `loopStart` から 1 周ちょうどを別のバッファへ写し、そのバッファ全体を `loop = true` で繰り返す（ループ点・開始位置を使わない）。
- 写すとき、頭の 30 ミリ秒を `loopEnd` の後ろの続きの音から混ぜる。MP3 の誤差や遅れの残りで端がずれても、最後 → 最初が同じ波形の続きになる。

**自動テストで言えること**: 写したバッファの最後 → 最初の段差は、曲の中の普段の隣り合う音の差より小さい（unit・E2E）。混ぜるのをやめると unit が落ちる。**実機で聞こえないことは保証しない**（§6）。

## 4. ゲームでの鳴らし方

| 場面 | 段 |
| --- | --- |
| 新しく始める | 剣士 |
| 洋館から戻る → 帰還の会話 → 交代の会話の間 | 剣士（主人公はまだ剣士） |
| 交代の会話を閉じた瞬間 | 魔法使い（以下、弓師・盗賊も同じ） |
| 時計塔の後、道の前 | 盗賊 |
| 道で影の旅人と会ってから撤退・全滅して戻る | 盗賊（進行どおり） |
| 道を終えて戻った、第一章の最後の会話の間 | 影の旅人 |
| 最後の会話を閉じた後・以後のロード | 完成版 |
| つづきから | セーブの進行と主人公から同じ式で決まる |
| テストモード | 完成版（進行を持たないため。今までと同じ） |

- 切り替え: 同じ位置から 2 秒でクロスフェード。前の段がまだ聞こえていない（鳴らし始めて 0.5 秒未満、最初のタップの前）ときは正しい段を頭から。
- 出撃すると止まり、酒場へ戻るとその時点の段を頭から（001 と同じ）。
- 次の段が読めないときは今の段のまま。最初から読めないときは手続き生成の BGM。音量設定・BGM オフはクロスフェード中も効く。
- 持つのは鳴らしている段のバッファだけ（デコード後 1 段 約 18MB。切り替えの 2 秒間だけ 2 段）。

## 6. 実機で確かめること（iPhone）

`docs/CHAPTER1_PLAYTEST.md` の A-01a・A-01b。

1. 新しく始めて、酒場で 2 周（約 1 分 40 秒）聞く。約 48 秒ごとの切れ目で、途切れ・無音・プツッがない。
2. 設定の BGM 音量（オフ / 小 / 中 / 大）で大きさが変わる。
3. 洋館をクリアして戻る → 交代の会話を閉じる。曲が止まらず・頭に戻らずに、フルートが加わる（約 2 秒）。
4. 出撃 → 撤退で酒場へ。今の段から鳴る。タイトルへ戻って「つづきから」でも同じ段。
5. （進められれば）道を終えて戻った最後の会話で影の旅人の段、閉じると完成版。
