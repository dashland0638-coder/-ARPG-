## 2. iPhone から使えなかった原因

**機能はあり、iPhone でも動く。開いた URL に `?dev=1` が付いていなかった**（PR のコメントの「通常プレイ」のリンク、または URL を手で開いた）。プレビューの帯は押せない作りで、テストモードへの案内も持たないため、画面からは入口があることが分からない。

## 3. 採用した方法: 優先案 A（既存のテストモードをそのまま使う）

- 入口は既存のまま: PR コメントの **テストモード** のリンク（`…/pr/<番号>/?dev=1`）。ホーム画面に置くなら `…/test/`
- 優先案 B（プレビュー限定の新しい入口）は**作らない**。既存の入口で目的を満たし、新しい UI は通常の画面に開発用の要素を増やすだけになるため
- 足したのは、幽霊船の検証地点のうち既存の開始地点に無かった 3 つだけ（既存の表と `gsTestWaypoint` に足す）

| 検証したいこと | 開始地点 |
| --- | --- |
| 1 入口 | 開始地点を選ばない（小舟の脇） |
| 2 船内の食堂 | **食堂の手前（往路）**（新）／ 食堂……?（帰還不能の後） |
| 3 点呼の廊下の残影 | **点呼の廊下の手前（甲板長）**（新） |
| 4 錨鎖を辿る帰還ルート | **錨の鎖を辿る道の始まり**（新） |
| 5 甲板長戦 | 点呼の廊下の手前（扉を開けて入ると点呼 → 甲板長） |
| 6 船長戦 | 錨鎖庫の前室（ボス戦直前） |
| 7 帰還イベント | 撃破後の船長室（昇降口 → 甲板 → 縄梯子） |
| 8 酒場の帰還後の会話 | 撃破後の船長室 → 縄梯子で酒場へ（弓師＋魔法使いの時に一度だけ） |

## 4. 変えないもの

通常プレイの仕様・UI・操作感、`?dev=1` の判定、プレビューの帯、セーブの分け方、テストモードの画面。人間の判断が要る事項は無かった（Escalation なし）。
