1. 通常プレイの魔法使いの最大 HP は **96**（実画面で確認。§2）。防御・被弾後の無敵時間・村での回復手段（薬草以外）は無い。
2. **回避しない戦い方は、逃げても攻めても撃破より前に倒れる。** 攻撃し続けると 3 発（本体 33 ×2 ＋ 段階移行の爆発 30 = ちょうど 96）で倒れる。
3. **振りかぶりを見て避け、向き直って撃ち返すと、薬草なしで勝てた**（2 / 2 試行）。ただし受けた 63〜93 のうち 30〜60 は予兆の無い段階移行の爆発で、1 試行は残り HP 3 だった。
4. PR #89（攻撃ボタンが処刑になる）の影響は、この戦闘では **ほぼ無い**。処刑は撃破の直前に 1 回だけ起き（攻撃を押し直す戦い方だけ）、撃破の時間も生死も変えなかった。
5. S5 は「ボスの振りかぶりの最初のフレームを読む」理想に近い操作（テストモードのデバッグ表示を使う）。**人が iPhone で同じように読めるかは未確定**。Human の実機確認が必要（§8）。

注（FACT。分析 §H）:
- **ボス戦の間、カメラはボスにロックオンし、移動キーはボス基準になる**（S = 離れる、W = 近づく、A / D = 横）。W2-T1 は「W = 北」の固定を前提にしていたが、S1 は長方形ではなく「離れる・横・近づく」をボス基準で回っていた。S1 の値は今回も同じ入力で測ったので比べられる。
- 回避すると、押し続けている攻撃キーのオートコンボが止まる（押し直すまで再開しない）。S4 は最初の回避の後ほとんど攻撃していない（W2-T1 の S4 の与ダメージが 5 回だったのはこのため）。
- 魔法使いの通常攻撃は **体の向きへ** 撃つ（`11-combat-actions.js:842-843`。基本職に自動の照準は無い）。後ろへ回避すると体がボスと逆を向く。S5 の初版はこれを考えずに向き直らなかったので、反撃が当たらなかった（§4.4 の S5x）。

## 6. 魔法使いの生存可能性の評価

| 戦い方 | 評価 | 根拠 | 確からしさ |
| --- | --- | --- | --- |
| 逃走中心 | **生き残れない** | 自動の逃げ方では 9.5〜9.7 秒（ボスの HP 約 76〜77%）で倒れる。被弾の大半は泡・分身・残響で、離れても減らない。撃破まで 40 個以上の薬草が要る | 実測。ただし人の逃げ方（泡・分身を避ける位置取り）は測っていない |
| 攻撃中心（回避なし） | **生き残れない** | 3 発で倒れる（3.6〜3.9 秒、ボスの HP 65%。段階 2 へ移った瞬間）。3 発目は予兆の無い段階移行の爆発 | 実測。再現性が高い（2＋2 試行で 0.25 秒以内） |
| 回避と反撃 | **生き残れる。ただし余裕は 1 撃分** | 振りかぶりを全部避けると、受けるのは段階移行の爆発（30）と開始時の 1 撃だけ。残り HP 3 / 33。爆発をもう 1 回か本体を 1 撃受けると倒れる | 実測。ただし振りかぶりを最初のフレームで読む理想に近い操作。人の操作では未確定 |

- **勝てるかどうかは「振りかぶりを読んで避けられるか」でほぼ決まる。**回避しない戦い方には、逃げても攻めても勝ち筋が無い。
- **段階移行の爆発は、どの戦い方でも最大 HP の 31〜63% を占めうる**（予兆なし。1 回 30、2 回で 60）。読んで避ける戦い方でも、ここで余裕が消える。
- ボスの振りかぶりは体の伸縮だけで、床の表示は無い（設計書 §2.1）。iPhone の画面で 0.55 秒（段階 3 は 0.40 秒）の振りかぶりを人が読めるかが、通常プレイの生存の分かれ目になる。

## 7. 数値の区別と、測定の制約・未確定事項

### 7.1 数値の区別

| 種別 | 例 |
| --- | --- |
| 確定値（コード・実画面） | 最大 HP 96、攻撃力 30、ボスの最大 HP 912、1 撃の値（本体 33・爆発 30 …）、段階の閾値 65% / 30%、薬草 1 個 19.2、第一章の村に回復の手段が無いこと |
| 実測値（この測定） | 撃破までの時間、倒れる時刻、被弾・与ダメージの回数と合計、段階の時刻、Break・処刑の回数、ボスの振りかぶりの回数 |
| 推定値 | 推定ゲーム内時間そのもの（rAF の間隔からの推定）、被弾の出どころ（値で分けた）、S5 の実際の戦闘時間（約 13〜14 秒）、薬草がある場合（§4.6 の CALC）、性格の差の影響 |

### 7.2 制約

- **通常プレイを最初から最後まで自動で測っていない。** この環境は実プレイの 1 割程度の速さで、村の 1 区画に 40 秒前後かかる（`tests/duskvillage.spec.js`）。道中の会話・扉・敵もある。代わりにテストモードの「最初に HP 1 になった時刻」を使った（§5 の前提つき）。
- 各戦い方 2 試行。同じ条件の差は小さい（倒れる時刻で 0.25 秒以内。S4 だけ 2.5 秒、S5 は残り HP 3 / 33 と差が大きい）が、乱数の幅は十分に見られていない。
- 自動の操作は人の操作ではない。S5 は Debug Info で振りかぶりの最初のフレームを読み、0.2 秒後に回避する。人の目で読むより有利な可能性が高い。ボスが最も近い敵でないと読めない（S5 では 91〜93% のフレームで読めた）。
- 被弾の出どころは値からの推定。ゲームのコードを変えずには確かめられない。
- テストモードだけの「途中の会話」が S2・S4・S5 で起きた。撃破までの時間に会話で止まった時間が入る。
- 推定ゲーム内時間は会話中も進む。描画は 1.6〜3.0fps で、1 フレーム 50ms 刻み。
- 試走で見つけた測定の誤り: メニューを閉じてから計測を始めるまでの間にボスの 1 撃を受け、被弾の累計が 33 ずれた。計測の開始をメニューを閉じるのと同じ JS の実行へ移し、本測定は直した後の spec で行った（試走の値は報告に使っていない）。W2-T1 の spec にはメニューを開く手順が無く、W2-T1 のデータでも最初の被弾は 0.7〜0.9 秒（S2〜S4）で記録されているので、W2-T1 の値はこの誤りの影響を受けていない。

### 8.1 準備

1. 公開版（`https://dashland0638-coder.github.io/-ARPG-/`、URL に `?dev=1` を付けない）を開く。ゲームを始めてからメニューを開き、メニューのバージョン表示「ver … (xxxxxxx)」の括弧の中（公開したコミット）が **`1205665` 以降**であることを確かめる（main がこの後に更新されていれば、その版で構わない。括弧の中をそのまま記録すれば、新旧は Agent が GitHub の main の履歴で確かめる。`1205665` と違っても確認を止めなくてよい）。
2. 宵待ちの村へ出撃できるセーブで「つづきから」。主人公は魔法使い、支援は剣士（自動で決まる）。
3. メニューを開き、**HP が 96 / 96、攻撃力 30** であることを確かめる（装備は初期のまま。第一章では変わらない）。薬草の数を記録する。
4. 村を進んでボスの前（水鏡の跡）まで行く。**ボスに話しかける前に** メニューで HP と薬草の数を記録する。

### 8.2 確かめる戦い方（各 1 回。倒れたら酒場に戻るので、村を歩き直す）

| ID | 戦い方 | やること |
| --- | --- | --- |
| A | 攻撃中心 | 回避しない・薬草を使わない。ボスの正面で攻撃を押し続ける |
| B | 逃走中心 | 攻撃しない・薬草を使わない。ボスから離れて逃げ回る（泡・分身も避けてよい） |

### 8.4 判定の基準

| 結果 | 判定 |
| --- | --- |
| C で、最初の 1〜3 回のうちに薬草なしで勝てる | **通常プレイで生存できる**（読んで避ける戦い方が成り立つ）。設計書 §8.3 の「初見で 1〜3 回」に合う |
| C で勝てるが、毎回残り HP がわずか、または薬草が要る | **ぎりぎり**。ボスの攻撃を足すと勝てなくなる見込み |
| C で 3 回とも倒れる | **通常プレイで生存できない**。HD-D5（設計書 §9）の判断が先 |
| A・B で勝てた | 自動の測定と食い違う。記録を添えて知らせてほしい（測定の前提を見直す） |

**判断を保留すべき場合**:
- ボス戦の開始時に HP が 96 未満、または薬草が 3 個以上あった（条件が違う。記録して、別に扱う）。
- 版の括弧の中が `1205665` より前だった。
- 途中で中断・通信の問題・操作の誤り（意図せず回避・薬草を使った等）があった。
- C を 1 回しか試せていない（1 回の失敗だけで「生存できない」とはしない）。

## 9. 次工程へ進むための判断基準（推奨）

1. **ボスの攻撃を足す（設計書の案 B の ①）前に、§8 の C の実機確認を行う。**
   - 自動の測定では、回避しない戦い方はすべて倒れ、読んで避ける戦い方も余裕は 1 撃分だった。依頼 §6「通常プレイで生存できない可能性が残る間は、ボスの攻撃を追加して難易度を上げない」に当たる状態。
2. 実機の C の結果で分ける:
   - 「生存できる」なら、案 B の ③（支援との連携）と ②（予兆の補修）から進めてよい。① の攻撃を足すかは、③② の後に再測定（同じ spec）して決める。
   - 「ぎりぎり」または「生存できない」なら、HD-D5 を先に決める。候補は設計書 §9 のとおり（回復の手段 / ボスの攻撃力 / 予兆の補修で被弾を減らす）。**数値を変える案は Human の承認が要る。**
3. どの場合も、**段階移行の爆発（予兆なし）の扱い** を最初に決めることを推奨する。攻撃中心の戦い方が倒れる 3 発目で、読んで避ける戦い方の被弾の大半でもある。設計書の HD-D6（予兆の補修。時間・半径・ダメージは変えず、見えるようにする）が当たる。
4. 改修の後の比較は、この spec（`tools/baseline/ch1-combat-baseline-w2t2.spec.js`）を同じ条件で再実行する。比べる値は「通常プレイなら倒れる時刻」「S5 の残り HP」「S1 / S3 の撃破までの時間」。
