### A-2. 落下の隙間（走査）
- 走査範囲: 79 枚の床の板の全ての辺（12.3 万点）。辺の外側がエリアの中（歩ける範囲）で、外が床の無い所か、1.0 を超えて低い所なのに、辺に立てる（当たりが無い）点を数えた
- 結果: **該当 10 点**。どれも坂の横の辺で、段差がちょうど 1.00〜1.01 をまたぐ境の 1 点（丘の坂 8 点・崖の坂 2 点）
  - 歩いては下りられない（`standableAt` は -1.0 まで）
  - 跳んで越えても、下の床（1.0 下）に着くだけ
  - 床の無い所へ落ちる隙間は **0**。unit 試験では 1.02 までを許す
- 移動は 0.22 ずつの小さな歩みで当たりを判定する（`13-update-loop.js:651`）ので、回避の速さで薄い当たりをすり抜けることも無い
- **結論: 地図の上には、落ちる隙間は見つからなかった**
  - 「落ちたように見える」体験として考えられるのは、§A-3 の下り坂の浮き（毎フレーム空中になり、足が止まって滑り落ちるように見える）
  - 落下（`handleVoidFall`）が起きるかどうかは、縁の近くのでたらめな動きで確かめる（§A-4）
  - Human が見た場所が分かれば、そこで追試する（未確認事項）

### A-3. 坂の歩き（再現と原因）
**再現**（修正前、`terrain-before.log`）。上りと横切りは問題なし。**下りでは、全フレームの 25〜60 % で足が浮いた**。

| 経路 | フレーム | 浮いた（跳んでいない） | 歩きの動きの途切れ | 足と床のずれ（立っている時） |
| --- | --- | --- | --- | --- |
| 崖の坂を上る | 77 | 0 | 0 | 0 |
| 崖の坂を下る | 81 | **45** | **45** | 0 |
| 石段を上る | 152 | 0 | 0 | 0 |
| 石段を下る | 148 | **86** | **86** | 0 |
| 高台の坂（上り下り） | 357 | **118** | **118** | 0 |
| 峠の山道（上り下り） | 246 | **69** | **69** | 0 |
| 丘の坂を斜めに | 188 | **46** | **46** | 0 |
| 坂を横切る | 65 | 0 | 0 | 0 |
| 原野 → 谷（下り坂二つ） | 194 | **38** | **38** | 0 |
| 宿場 → 原野・谷 → 山道・山道 → 道の果て（上り） | — | 0 | 0 | 0 |

**原因**
1. 床の板の世界の縦の処理（`13-update-loop.js:696-767`）には、立っている者を下り坂へ吸い付ける処理が無い
   - 毎フレーム、重力の分（22·dt²）しか下がらない
   - 坂は歩く速さ × 傾きで下がるので、足が床より上に残り、`grounded = false` になる（空中扱い）
2. 歩きの動き（`updateLocomotion`、定義 `13-update-loop.js:1174`、呼び出し `:808`）は `moving = state.grounded && ...` で決まる
   - 空中扱いのフレームでは脚が止まり、足音と土煙が途切れる
   - 立っている時の構え（`05-rendering-rig.js:3720,3809`）も外れる
   - 浮く → 止まる → 着地する → 歩くが、フレームごとに入れ替わる。これが「**滑る・足が細かく震える・浮く**」の正体
3. 「足が埋まる」: 通り道の板の上の面が、床より 0.08 上にあった（`road2BuildPaths` の y = g + 0.05、厚さ 0.06）。足は床の高さなので、道の上では 8 cm 埋まって見える
4. 移動の速さ: 水平の速さは坂でも同じ（坂に沿った速さは 1/cos 倍、急な崖の坂で +4 %）。目で分かる差ではない。不自然に見えたのは 2 の止まりと着地のくり返し

**時計塔**
- 同じ縦の処理を使うので、坂の下りで同じことが起きうる
- Human の条件「他のマップに副作用がないこと」に従い、今回は道だけに効かせた（Agent Decision）
- 時計塔の坂の浮きを計測する別の Work Item を置く（`CT-SLOPE-FLOAT`。計測してから扱いを決める）

**演出中の縦の処理**
- 演出中の縦の処理（`02-world-common.js:1501-1509`）にも、下り坂へ吸い付ける処理が無い
- 演出で人物を坂の下りへ歩かせると、体が少し浮く（`grounded` は落ちないので、脚は動く）
- 道の会話を坂の上に置く時（例: 峠の山道の R4-06）に扱う（R3-4 の注意点）

## Phase C — 5 エリアの景観の完成案（R3-T2）
方針: 物の数より、**地形の輪郭・視線の誘導・素材・色・光・遠景・ランドマークの見え方**。既定のカメラで遊んで分かることを基準にする（R3-T のスクリーンショットでは、既定のカメラは足元 20〜30 m を真上寄りに映す）。

| エリア | 今の状態（R3-T） | 完成案 |
| --- | --- | --- |
| 旅人の宿場 | 箱の家に三角の屋根、庇と看板、敷石、塀と門 | **輪郭**: 家に軒・張り出した二階・崩れた壁の穴（廃墟感）。屋根を寄棟と切妻に分け、一部を落とす。**生活感**: 干した布・空の荷車・閉じた戸・井戸の桶。**素材**: 敷石の目地と、端の草。**光**: 朝の低い光で、通りに家の影が落ちる（影の向きは既存の太陽）。**誘導**: 通りの奥に門と道標が見え続ける |

**カメラ（Human の判断: HD-2）**

  - B: 道だけ、見晴らしの地点（高台・峠・道の果て）で、一時的にカメラを引く演出（`sceneCamShot` の作法）

### Escalation HD-2: 景色を見せるためのカメラ
- Trigger: E-3（ゲームデザイン上の意味が大きく違う複数案）、E-1（共通のカメラの仕組みに触れる場合）
- Facts
  - 既定のカメラは近く、真上寄り（`getCamOffset`、`13-update-loop.js:2161`、`CAMHEIGHT_STEPS`、`14-hud-boot.js:160`）
  - 遊んでいる画面では足元 20〜30 m しか映らず、遠景・高低差・ランドマークは見えにくい（R3-T のスクリーンショット）
  - カメラは全ダンジョン共通
- Why Agent cannot decide: 見晴らしを見せるために、遊んでいる最中のカメラを動かすかどうかは、体験と他のダンジョンへの影響の判断
- Options
  - **A**: 変えない。地面の近くの物で個性を出す（今の方針）
    - 影響: 他に影響なし。遠景はほとんど見えない
  - **B（推奨）**: 道だけ、見晴らしの地点（宿場の門・高台・谷の入口・峠・道の果て）で、一時的にカメラを引いて遠景を見せる（`sceneCamShot` の作法。数秒で戻る）
    - 影響: 他のダンジョンに影響なし。見せたい所だけ遠景が見える
  - **C**: 道だけ、既定のカメラの高さと距離を引く
    - 影響: 道を歩く間ずっと広く見える。操作の感覚が他のダンジョンと変わる
- Recommendation: B。理由: 共通の仕組みを変えずに、第一章の最後の景色を見せられる
- Minimal answer: 「A」/「B」/「C」

### Escalation HD-3: 盗賊の古い羅針盤は、盗賊が盗んだ物そのものか
- Trigger: E-2（`docs/CHAPTER1_STORY.md:152`「何を盗んだか、誰から盗んだかは具体的には語らない」）、E-1（`docs/CHARACTERS.md:72`「友人の宝を盗んだ過去」）
- Facts
  - 依頼文の設定は「盗賊が過去に持ち帰った品。正確に北を指さない。返せずに持ち続けている」
  - 時計塔では「持ってっちゃいけない物を持って」出ていったと語る（§4-4）
- Why Agent cannot decide: 羅針盤を盗んだ物とすると、第一章で語らないと決めた盗みの具体を一つ示すことになり、既存の決定と矛盾しうる
- Options
  - **A（推奨）**: 盗んだ物とは結ばない。「昔、持ち帰った品。返しそびれている」とだけ言う（盗みの話と同じかどうかは語らない）
    - 影響: 既存の決定を守る。羅針盤の意味は曖昧なまま残る
  - **B**: 羅針盤が盗んだ物（友人の宝）だと分かる
    - 影響: §4-4 と CHARACTERS の決定を変える。盗賊の物語に区切りがつく（返す・返さないが第二章の話になる）
- Recommendation: A。理由: 怪異と同じく「答えを出さない」第一章の方針に合う
- Minimal answer: 「A」/「B」
