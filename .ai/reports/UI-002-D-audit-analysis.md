### 問題が無かった観点（根拠）

- **1280×800 への影響**: 844×390 用の変更はすべて `@media (max-height: 500px)` の中。1280×800 PC で常時表示 UI の中央侵入・要素同士の重なりはなし（実測）。制限時間はボスバーの下（D6 の意図どおり）
- **844×390 のゾーン**: Character / Mini-map / Action Zone の常時表示は中央に入らない（実測、safe-area あり・なし）。Action ボタン・コンボ・スティックは互いに重ならない
- **通知の責務（D5）**: D6 で `spawnToast` / `spawnLog` の呼び出しの変更なし（`git diff f988c66..30e2d30 -- src`）。`notification-channels.test.js`（呼び出しの組・`pushMsgLog` の経路）が守っている
- **z-index**: 処刑 23 > インタラクト 22 > ログ 21 > HUD 16 > タッチ 15。プロンプトはログ・タッチ UI より上でタップを受け取る。メニュー・会話（30 / 35）が出ている間はプロンプトを出さない（`canTryExecution`・`updateInteractPrompt`）
- **safe-area**: 844×390 の各ゾーン・ボスバー・ログ・コンボは inset の内側（D6 E2E と実測）
- **複数対象**: 処刑の対象は 1 体（`pickExecutionTarget`）、インタラクトは処刑を避ける（unit）。インタラクトの対象の選び方と位置の参照順は一致している（`updateInteractPrompt` / `interactTargetWorldPos`）
