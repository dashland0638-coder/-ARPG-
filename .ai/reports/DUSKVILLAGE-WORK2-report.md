## 3. 新規実装したもの

### 3-1. マップ骨格（15部屋 / 論理10エリア）

```
湖畔の森道 → 木橋 → 村の入口 → 中央広場 ┬ 魚屋への小道 → 魚屋
                                          │      └ 船着き場への小道 → 船小屋
                                          ├ 住宅への小道 → 住宅
                                          └ 商店街 → 水門前 → 水門 → 村の奥 → 水鏡の跡(ボス)
```

- 部屋数を論理エリア数に1:1で合わせていない（小道4本は `cor:true`。場所名は手前の部屋を引き継ぐ）
- 中央広場を中心に4方向へ枝を出し、「広場に戻ってくる」動線にした
- 村入口の手前に2棟を置き、入口から村全体を一望させない
- 水門前は建物を1棟に減らし、舫い杭だけを並べて水面を広く見せる
- 村の奥は人工物をほぼ置かず、静かな水面と灯り1つだけ
- 旧「蜘蛛の巣状の細い桟橋」は完全に撤去（ユニットテストで旧部屋idの不在を固定）

### 3-2. 建物と生活の跡

- 主要建物 **13棟**（入れる5棟 ＋ シルエット8棟）
- 入れるのは 魚屋 / 住宅 / 船小屋 / 商店 / 水門の管理小屋
- 小物: 魚籠・まな板・包丁・桶・秤・木箱・机・椅子・食器3人分・布団・木彫りの玩具・棚・
  舟3艘・網・浮き・ロープ・滑車・修理途中の道具・空の商品棚・看板・歯車・鎖・レバー・井戸・掲示板
- ロアは **7点**（道標・掲示板・魚屋の帳簿「水門の件について――」・木彫りの舟・修理台の道具・
  商店の帳簿・水門の記録）。読まなくても本筋が分かる補助に留めている

### 3-3. 環境アニメーション（最小実装）

`duskProps` 配列 + `updateDuskVillage()` 内の `switch` だけ。汎用システムは作っていない。

| kind | 対象 | 動き |
| --- | --- | --- |
| `boat` | 小舟3艘 | 上下＋左右の傾き。**プレイヤーが4.6以内に入ると揺れが増える** |
| `float` | 浮き | 水面で上下 |
| `cloth` | 洗濯物・網 | 面の傾きとはためき |
| `sign` | 看板 | 振れ |
| `swing` | 釣瓶・秤 | 吊り下がって前後に振れる |
| `ropeSag` | ロープ | たわみの上下 |
| `reeds` | 水際の草 | 傾き（群ごとに1登録） |
| `spin` | 滑車 | わずかな回転 |
| `lamp` | 灯り8基 | 位置ではなく**明るさ**で炎の揺らぎ |
| `sway` | 木・布看板・鎖 | 振れ |

位相・周期はプロップごとに別（`freq` は割り切れない値）。「全部が同じ拍で揺れる＝ゲームのループ」
に見えるのを避けるため、周期を揃えていない。

水面は分割平面（26×46）の頂点を、直交する2波＋斜めの1波で毎フレーム動かす。

### 3-4. プレイヤーへの反応

- **水際を歩く** → 部屋の縁2.2以内で移動中に、0.55秒間隔で波紋が立つ
- **小舟に近づく** → 舟の揺れが増え、舟の周りに波紋が広がる
- **木橋を渡る** → 移動中に1.1〜2.0秒間隔で板が軋む（`woodCreak`）

波紋は同時10枚まで。使い捨てで専用プールは作っていない。

### 3-6. 環境音

`duskShore`（風・葉ずれ・遠くの鳥）/ `duskVillage`（家鳴り・水音・床板）/

足音は 森=土 / 広場・入口=石 / それ以外=板張り。

### 3-7. 部屋テーブルを core へ

`src/core/dusk-village-map.js`（新規）に `DUSK_ROOMS` と問い合わせを出した。

**理由**: 部屋テーブルの間違いは「到達できない区画」「開かない開口」として出るが、
ヘッドレス（SwiftShader）は実プレイの **約1割** の速度しか出ず、村の端まで歩く E2E は
1区画あたり40秒前後かかって現実的でない。表そのものを `tests/unit/` で縛る形にした
（`core/mansion-enemies.js` などと同じ、HEADER 経由の import）。

## 7. 残課題・要判断事項

**実装を止める理由にはならないが、記録しておくもの。**

### 7-1. ボスエリアが空である（想定どおり）

`duskCollective` を撤去し、「村の残響」は WORK 7 のため、現在ボスエリアには何もいない。
ボス扉は鍵なしで開く。結果として **このシナリオは現在クリアできない**（撤退・帰還は可能）。
旧ボスに紐づくデータ（`BOSS_ENDING_LINES.duskCollective` / ボスbark / ドロップ接頭辞
`08-loot-equipment.js` / 見た目分岐 `06-player-enemy.js:5111`）は、WORK 7 で作り替える前提で
**手を付けずに残してある**。

### 7-2. 敵がいない（想定どおり）

WORK 3 以降で水鏡の影・泡沫の群れ・写し身・記憶漁師・水門守の残響を足す。
`07-ai-combat.js` の `_spawnWorldKey==='duskvillage'` 分岐は、足していくための空の受け皿にしてある。

### 7-3. 歩行速度と E2E の費用対効果（**要判断**）

この環境の実測で、プレイヤーの移動はおよそ **0.5 units/秒**（実プレイの約1割）。
村の全長（z 284→534、250 units）を歩くと **8分以上** かかる。

そのため E2E は「入口 → 村の入口 → 中央広場」までに絞り（2.6分）、
枝と奥の連結はユニットテストで固定した。**枝の開口へ寄せる操作は秒数の揺れで
不安定になり、実際に一度フレーキーになった**（壁沿いに詰める操作で、
パルス間隔 900ms では通り、700ms では通らなかった）。

判断が必要な点: このまま「歩行の E2E は入口側だけ・幾何はユニットテスト」で進めるか、
実機確認用に別の手段（テストモード専用の座標ジャンプなど）を用意するか。
**今回は新しいデバッグ機能を足していない。**

### 7-4. 周回・報酬まわりの未設定（WORK 0 から継続）

- `BOSS_ABILITIES` に `duskvillage` のボス能力が無い
- `SCENARIO_TIME_LIMIT_BASE` に `duskvillage` が無い（周回しても制限時間が付かない）

いずれも「村の残響」を実装する WORK 7 で、ボスの正式仕様と合わせて決めるのが自然。

### 7-5. 村の密度と見え方（WORK 8 向け）

薄暮〜夜の色設計のため、広場は意図どおり暗い。実機スクリーンショットで見る限り
「歩けるが、まだ少し寂しい」状態で、小物の追加・灯りの数・霧の濃さは
WORK 8（全体演出／バランス）で詰める前提。

### 7-6. 中央線に物を置かない制約

見下ろしカメラ（プレイヤーの8m上・6m後ろ）の正面に背の高い物を置くと、
視線と通り道を同時に塞ぐ。井戸・灯り・木立・木箱は **x=0 の動線から外してある**。
WORK 3 以降で小物を足す際も同じ制約が効く（実装時に一度これで詰まった）。
