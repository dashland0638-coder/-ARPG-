# Decision

## ID

DEC-001

## Date

2026-09-21

## Decision

宵待ちの村（`duskvillage`）を、既存実装の拡張ではなく
**正式シナリオ仕様へのリビルド**として扱う。

- 正式テーマ: **「忘れられること」**
- 正式構造: 村入口 → 中央広場 → 魚屋 / 住宅 / 船小屋 / 商店街 → 水門前 → 水門 → 村の奥 → 村の残響 → 夜明け
- ボス `duskCollective` は **「村の残響」へ置き換える**。台詞・演出・見た目・ドロップ・E2E も新仕様へ更新する
- 既存E2Eは削除せず、「村の残響」を検証するテストへ置き換える

### 継承しないもの（ゲームデザイン）

- 灯りが怪異を引き出すギミック
- ランタン点灯による敵出現
- 濡れた村人 / 影の子供
- `duskCollective`
- 光を当てないと無敵になるボス仕様

ランタンは背景・環境オブジェクトとしては残してよい。中核ギミックにはしない。

### ゲームループ

「灯りを当てる」ではなく **「観察する → 違和感を見つける → 見分ける → 誘導する」**。

### 個別の決定

| 項目 | 決定 |
| --- | --- |
| 水門 | シナリオ上の関門。鍵集め・複数レバー・アイテム探索の大規模パズルにしない。水門守の残響との戦闘・観察を経て開く |
| 観測の灯（Skill 2） | 正式仕様に含める。答えを直接表示しない。本体候補の輪郭・波紋の違い・攻撃前の挙動・コピー状態・環境の小さな異常を「判断しやすくする」だけ。使わなくても攻略可能 |
| 幻影歩法（Skill 1） | MAGE-001 と同一の仕組みを使う。宵待ちの村専用の別実装を作らない。幻影を攻撃対象候補として扱える汎用構造を優先する |
| 遅延攻撃 | 記憶漁師用に新規実装。館の主の遅延追撃を参考実装として使う。プレイヤー位置履歴を記録する汎用の仕組みにする |
| 写し身 | 直前の攻撃を記録し、一度だけコピーして再生。Attack Snapshot（攻撃種別・対象・方向・位置）を使う最小構成から。今回だけのハードコードにしない |
| 環境アニメーション | 巨大な汎用システムを作らない。`duskProps` + `Math.sin` 等の最小実装から開始 |

### 設計原則（不変）

- 魔法に属性を追加しない。弱点表を作らない
- 魔法の違いは挙動・軌道・距離・範囲・タイミング・敵との相互作用で表現する
- 魔法使い専用の必須進行ルートを作らない。観測の灯／幻影歩法を使わないと進めない場所を作らない
- 敵は他職でも撃破可能。魔法使いは「より効率的・情報を得やすい」立場
- 村人を復活させるのではなく、残された記憶が解放される。撃破後は静かな村が残る
- 最後の記憶の言葉は「……ありがとう。」

### Test Mode

Scenario Test Mode を先に完成させる。起動順序は必ず:

```
finishEnteringGame({world:'training'})   →   launchScenario(scenarioKey)
```

`finishEnteringGame({world:'duskvillage'})` を直接テスト起動に使わない
（`state.testMode` が false になり、テスト中にセーブが上書きされる恐れがあるため）。

### 禁止事項

- Chapter という新しい runtime state を作らない（`state.chapter` を追加しない）
- `CHAPTER_CAST` をシナリオ進行管理に流用しない
- 本編の Chapter 1 進行を変更しない
- save/load 仕様を変更しない
- `SCENARIO_DEFS` を勝手に別仕様へ変更しない
- 既存の `launchScenario` / `launchScenarioNow` を不要に変更しない
- 既存システムと重複する実装を作らない
- 既存コードを動く理由なく全面削除しない

## Reason

`WORK 0` の調査（`.ai/reports/DUSKVILLAGE-WORK0-analysis.md`）で、`duskvillage` は既に
実装済みだが、テーマ・マップ構造・敵・ボスのいずれも今回の正式仕様とは別物であることが
判明した。両立させると「灯りギミック」と「観察・見分け」という2つのゲームループが
1ステージに同居し、どちらも中途半端になる。ゲームデザインは置き換え、実装資産
（部屋テーブルの authoring パターン・昼夜の色補間・水面・ボス骨格・VFX）は再利用する。

## Alternatives Considered

1. **既存を残して別区画を足す** — 却下。テーマが二重になり、村の規模も想定
   （初回探索15〜25分）を超える
2. **既存の灯りギミックを観察ループへ転用する** — 却下。「灯りを当てる」は答えを
   与える操作で、「自分で見分ける」という今回の中核と方向が逆
3. **新しい world key を作って旧 duskvillage を温存** — 却下。`SCENARIO_DEFS` と
   `CHAPTER_CAST` の対応（Arc 2 = 宵待ちの村 = `duskvillage`）が壊れる

## Consequences

- `14-dungeon-duskvillage.js` の `DUSK_ROOMS` / 敵 / ボス / ランタンギミックは作り替わる
- `07-ai-combat.js:561` の `duskvillage` 敵配置、`06-player-enemy.js:5111` のボス見た目分岐、
  `12-progression-ui.js` のボス台詞・撃破演出、`08-loot-equipment.js` のドロップ接頭辞が更新対象になる
- `tests/duskvillage.spec.js` は新仕様の検証テストへ置き換える
- `BOSS_ABILITIES` / `SCENARIO_TIME_LIMIT_BASE` に `duskvillage` のエントリが無い件は、
  「村の残響」実装時（WORK 7）に合わせて判断する
- 幻影歩法は MAGE-001 と同一実装なので、WORK 4以降で MAGE-001 の成果物に依存する
