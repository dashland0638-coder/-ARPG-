DEC-038（CHARACTER-VIS-002 T-2 Human Review の判断 H-1〜H-4: 顔は O1、職ごとの目は B、BGM 対策を実装、髪の貫通を修正）

## Decision

Human が T-2 Human Review（`.ai/reports/CHARACTER-VIS-002-T2-human-review.md`）の判断事項 H-1〜H-4 に回答した。

- **H-1 = O1（既存の頭のメッシュの拡張）**: 頭の前後の奥行きを増やし、額・頬・鼻・口元・顎が自然につながる形にする。頬の膨らみと顎の丸み、眼窩と目の周りの奥行き。正面・45°・横・下からで自然に。髪・帽子・輪郭線を新しい頭の形に正しく追従させる（頭の形のデータを共有しているものへの影響を必ず確かめる）。別メッシュの継ぎ目・輪郭線の不整合を増やさない
- **H-2 = B（職ごとの目の変化は少しだけ）**: 変えてよいのは**目尻の角度**と**横幅と縦幅の比率**だけ。共通の基準から ±10% 以内。目の基本の大きさ・瞳孔の大きさ・白目の色・T-1 で承認された目の基本の造形は共通のまま。差を誇張しない。目だけで個性を作らず、頭の輪郭・頬・顎・表情と組み合わせる。**各職の目の変更値とデザイン上の理由を記録する**
- **H-3 = 実装する（BGM の重複対策）**: 裏に回ったら音を一時停止し、戻ったらゲームを始めた後かを確かめてから再開する。タイトルで酒場の BGM を鳴らさない。場面の切り替えで古い BGM を残さない。同時に複数の BGM を鳴らさない。開発モードだけ BGM の数の表示。音響システムは作り直さない。iOS Safari のライフサイクルを考える。自動テストで確かめる範囲と iPhone 実機（Human）の範囲を分ける。**実機の確認の前に修正完了と断定しない**
- **H-4 = 実施する（髪の貫通の修正）**: O1 とあわせて行う。後頭部の幅・奥行きに合う髪の輪を足す。髪が頭の内側に入らないようにする。`napeSideIn` を再評価する。帽子を被っても頭と髪の関係が破綻しない。4基礎職と上位4職で確かめる。影の旅人の見た目・既定の形に影響させない。頭と髪の貫通を検出するテストを足し、後頭部・横でも検証する
- **実装の順**: T-2R-1 BGM → T-2R-2 顔の確認のプレビュー → T-2R-3 共通の頭の拡張と髪の貫通の修正 → T-2R-4 職ごとの顔 → T-2R-5 上位職。各段階で独立 Reviewer と必要なテスト。Human の目視が要るものはプレビューを提示し、確認を得てから次へ
- **最終の品質基準**: 顔のパーツを増やすことが目的ではない。顔全体の自然な立体・頬 / 鼻 / 口元 / 顎のつながり・横や斜めで平面的に見えない・顔つきで職の個性・4.75 頭身の可愛らしさ・髪 / 帽子と頭の自然なつながり・影の旅人は不変・ポリゴン数と Material 数の予算を確かめ、増える分は明示
- **制約**: PR #149 の base / head を変えない。PR #149 を merge しない。main へ統合しない。T-3 に着手しない。CI の不安定さの調査は分ける。設計の矛盾・既存仕様への影響は Human へ。T-2 の最終承認と T-3 への進行は Human が改めて明示するまで保留
